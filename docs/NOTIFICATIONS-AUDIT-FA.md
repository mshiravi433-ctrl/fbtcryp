# ممیزی سر‌به‌سر نوتیفیکیشن — ۲۰۲۶-۰۸-۲۱

این سند مسیر وب‌پوش و FCM داخل APK را از ثبت‌نام تا تحویل و تپ‌کردن بررسی می‌کند.

## نتیجهٔ فعلی

- مرورگر/PWA از VAPID و `POST /api/push/subscribe` استفاده می‌کند.
- APK از `@capacitor/push-notifications` و FCM استفاده می‌کند و توکن را به
  `POST /api/push/fcm` می‌فرستد.
- `initNativePushListeners()` در شروع برنامه یک بار listenerهای دائمی را نصب
  می‌کند. هر توکن جدید FCM دوباره ثبت می‌شود و watchهای سفارش با هویت جدید sync
  می‌شوند؛ بنابراین چرخش بی‌صدای توکن، دستگاه را از دسترس خارج نمی‌کند.
- تپ روی نوتیفیکیشن native فقط به مسیرهای داخلی `/orders`، `/intent` و `/swap`
  هدایت می‌شود. URL خارجی یا مسیر ناشناخته رد می‌شود؛ open redirect ممکن نیست.
- Service Worker وب، نمایش نوتیفیکیشن، کلیک و کش shell نسخه‌دار را انجام می‌دهد.
- مجوز در وب از `Notification` و در APK از مجوز واقعی Capacitor خوانده و
  درخواست می‌شود؛ کد native به نبودن global `Notification` وابسته نیست.

## کلیدها و تطابق پروژه

کلید عمومی وب `VITE_VAPID_PUBLIC_KEY` در build کلاینت است؛ کلید خصوصی
`VAPID_PRIVATE_KEY`، subject و اعتبارنامهٔ سرویس FCM فقط در Environment Variables
سرور قرار می‌گیرند و نباید در Git باشند. پروژهٔ Firebase واقعی APK:

```text
fbtswap-36b13
```

`android/app/google-services.json` نیز همین project id را دارد. هر راهنمای قدیمی
که `fbt-room-a46fc` می‌گوید باید به‌روز یا نادیده گرفته شود.

## راستی‌آزمایی پیشنهادی

1. `npm test` — تست‌های wiring و probeهای push.
2. `npm run build` — اطمینان از import و bundle کلاینت.
3. در محیط عملیاتی `GET /api/push/status` را بررسی کنید؛ این endpoint فقط وضعیت
   و شناسهٔ پروژه را گزارش می‌کند و رازها را افشا نمی‌کند.
4. برای FCM، self-test سرور باید احراز هویت موفق و پروژهٔ قابل دسترس را نشان دهد؛
   توکن آزمایشی عمداً معتبر نیست و هیچ دستگاهی پیام دریافت نمی‌کند.
5. پس از deploy، روی Android 13+ اجازه را بدهید، token را در لاگ امن/داشبورد
   ثبت‌شده بررسی کنید، سپس یک order watch و تپ نوتیفیکیشن را آزمایش کنید.

## نکتهٔ عملیاتی

ثبت‌نام کاملاً opt-in است. صفر بودن subscribers/devices به معنی خرابی نیست؛ یعنی
هنوز کاربری اجازهٔ نوتیفیکیشن نداده است. کران روزانه نیز فقط زمانی ارسال می‌کند
که secret و scheduler محیط عملیاتی تنظیم شده باشند.
