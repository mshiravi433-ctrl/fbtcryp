> سند فارسیِ گزارش «شبکه‌های S · MINT · BREA · UNI · Mon · Scr · Zk · Rabinhood
> مانند دیگر شبکه‌ها تحلیل هوش مصنوعی توکن، رلهٔ خصوصی و ریسک MEV و محافظت،

## ۲) تحلیل هوش مصنوعیِ توکن (اسکن امنیتی GoPlus)

### علت ریشه‌ای

`src/lib/tokenRisk.js` نگاشتِ کوچکی داشت که در **۵۹۱۴۴ (Linea)** تمام می‌شد:

```js
export const GOPLUS_CHAINS = { 1:'1', 56:'56', 137:'137', 42161:'42161',
  10:'10', 8453:'8453', 43114:'43114', 59144:'59144' };
```

`TokenRiskCard` و `RwaRiskPanel` هر دو با `goplusChainId(chainId)` تصمیم
می‌گیرند و **وقتی پاسخ `null` است هیچ چیز رندر نمی‌کنند**. یعنی کارتِ تحلیل روی
آن هشت شبکه «خراب» نبود — اصلاً وجود نداشت. سرور هم همان هشت آی‌دی را در
`server/tokenRisk.js` و `server/securityIntel.js` رد می‌کرد (۴۰۰
`UNSUPPORTED_CHAIN`).

### چه شد

هر سه نگاشت به **همهٔ ۱۶ شبکهٔ EVM رجیستری** گسترش یافت. هر آی‌دی از جدولِ
خودِ GoPlus گرفته شده، نه حدس زده شده:

> منبع: `docs.gopluslabs.io` → «Response Details» (فهرستِ `id | name`، برچسب
> «Updated 13 days ago» در تاریخ خوانش ۲۰۲۶-۱۰-۰۳). آی‌دی‌های مربوط: ۱۴۶ Sonic،
> ۵۰۰۰ Mantle، ۸۰۰۹۴ Berachain، ۱۳۰ Unichain، ۱۴۳ Monad، ۵۳۴۳۵۲ Scroll، ۳۲۴ zkSync
> Era، ۴۶۶۳ Robinhood.

فایل‌ها:

| فایل | تغییر |
|---|---|
| `src/lib/tokenRisk.js` | `GOPLUS_CHAINS` ← ۱۶ زنجیره |
| `server/tokenRisk.js` | `ALLOWED` ← ۱۶ زنجیره (پروکسی تنها راهِ رسیدن مرورگر است) |
| `server/securityIntel.js` | `GOPLUS_CHAINS` ← ۱۶ زنجیره (اسکن approvalها) |
| `server/providerStatus.js` | ردیف `goplus-token-risk` دیگر فقط هشت شبکه را گزارش نمی‌دهد |

### مرز صادقانه

پشتیبانی از `chainId` به معنای داشتنِ **داده برای هر توکن** نیست. GoPlus به‌ازای
قرارداد پاسخ می‌دهد؛ توکنِ تازه یا کم‌نقدشندگی خالی برمی‌گردد و موتور امتیاز
`unknown` می‌دهد — هرگز «safe». اسکنِ نشدنی همچنان `risk.unknown` است، نه برچسب
سبز.

## ۳) رلهٔ خصوصی و ریسک MEV و محافظت

### اینجا باگ، برعکسِ دو مورد دیگر بود: ردیف‌ها بودند ولی **دروغ** بودند

`PRIVATE_RELAYS` برای هر هشت شبکه یک ردیف داشت — ولی همه با کپیِ یک خط ساخته شده
بودند:

```js
// Sonic - dRPC MEV-protected
146: { id:'drpc', name:'dRPC MEV-Protected', rpc:'https://sonic.drpc.org', … }
// …همین برای Mantle / Berachain / Unichain / Monad / Scroll / zkSync…
4663: { id:'publicnode', name:'PublicNode MEV-Protected',
        rpc:'https://robinhood-rpc.publicnode.com', … }
```

دو ادعای غلط در این چند خط:

1. **dRPC محافظتِ MEV را برای این زنجیره‌ها نمی‌فروشد.** مستنداتِ خودِ dRPC
   می‌گوید MEV protection یک افزونهٔ **Premium** است و دقیقاً **پنج** زنجیره را
   فهرست می‌کند: Ethereum · Base · BNB Smart Chain · Arbitrum · Solana.
   (منبع: `drpc.org/blog/mev-protection-nodes/`.)
2. **`robinhood-rpc.publicnode.com` وجود ندارد.** PublicNode میزبانِ این شبکه
   نیست و چنین هاستی را سرویس نمی‌دهد.

یک برچسبِ رله **قول است دربارهٔ جایی که تراکنشِ امضاشده می‌رود**. قولِ «ممپول
خصوصی» روی endpointای که به ممپولِ عمومی می‌فرستد، دقیقاً همان خطایی است که
`src/lib/mevProtection.js` برای جلوگیری از آن نوشته شده.

### چه شد: به‌جای یک جمله برای همه، مدلِ ممپولِ هر شبکه

`src/lib/mev.js` حالا دو چیز دارد:

**(الف) `PRIVATE_RELAYS` با فیلدِ `kind`** — اسمِ هر ردیف همان است که واقعاً هست:

| شبکه | kind | مسیر |
|---|---|---|
| Mantle ۵۰۰۰ | `sequencer` | `rpc.mantle.xyz` — تک‌سِکوئِنسِر، ممپول عمومی ندارد |
| Unichain ۱۳۰ | `encrypted` | `mainnet.unichain.org` — TEE builder + ممپول رمزنگاری‌شده |
| Scroll ۵۳۴۳۵۲ | `sequencer` | `rpc.scroll.io` — ممپول خصوصی، ترتیب FCFS |
| zkSync Era ۳۲۴ | `sequencer` | `mainnet.era.zksync.io` — ممپولِ «فقط سِکوئِنسِر» |
| Robinhood ۴۶۶۳ | `sequencer` | `rpc.mainnet.chain.robinhood.com` — Arbitrum Orbit، تک‌سِکوئِنسِر |

**(ب) `MEV_CHAIN_MODEL`** — برای **همهٔ ۱۶ زنجیره**: نوعِ ممپول
(`public` / `private` / `encrypted`)، شیوهٔ ترتیب (`fcfs` / `priority` /
`builder`) و یک ضریبِ تعدیلِ ریسک (`riskBias`).

چرا ضریب؟ امتیازِ ساندویچ از «لغزش × تأثیر قیمتی × اندازه» ساخته می‌شود و
نمی‌داند **چه کسی می‌تواند سفارش را پیش از ثبت ببیند**. روی زنجیره‌ای که ممپول
عمومی ندارد، مهاجم نمی‌تواند تضمین کند هر دو پایِ ساندویچ در یک بلوک بیفتد —
کاری که روی اتریوم atomic است. گزارشِ همان عددِ اتریوم روی Scroll، **بزرگ‌نماییِ
خطر** است؛ و برعکس. مطالعهٔ تجربیِ ۲۰۲۶
(`arxiv.org/pdf/2601.19570`) دقیقاً همین را می‌گوید: ساندویچ روی L2ها
«probabilistic است نه atomic»، چون سِکوئِنسِرِ متمرکز و ممپولِ خصوصی تضمینِ
هم‌ورودی را از مهاجم می‌گیرد. تابعِ `chainAdjustedRisk()` این تعدیل را اعمال
می‌کند و **عددِ خام را هم کنارِ عددِ تعدیل‌شده نگه می‌دارد** (`rawScore`) تا چیزی
پنهان نشود.

### سه شبکه‌ای که واقعاً رله ندارند

**Sonic (۱۴۶)، Berachain (۸۰۰۹۴) و Monad (۱۴۳)** زنجیره‌های لایه‌یک با ممپول
عمومی هستند و هیچ رلهٔ خصوصیِ عمومی و مستند برایشان پیدا نشد. برای این‌ها
`privateRelayFor()` عمداً `null` برمی‌گرداند و کارت می‌گوید:
«این شبکه تراکنش‌های در انتظار را منتشر می‌کند و ما نتوانستیم رلهٔ خصوصی برایش
تأیید کنیم. اسلیپیج تنگ همچنان بهترین دفاع است.»
(جملهٔ قدیمی — «هنوز رله‌ای روی این زنجیره نیست» — دروغِ کوچکی بود: «هنوز» یعنی
در راه است.)

**اما این به معنای «برای همیشه نه» نیست:** `relayOverride()` متغیر محیطیِ
`VITE_MEV_RELAY_<chainId>` را می‌خواند. استقراری که برای یکی از این زنجیره‌ها
endpoint خصوصی بخرد (مثلاً از ارائه‌دهندهٔ Premium)، بدون تغییر کد همان را
استفاده می‌کند. شرط: فقط `https://` — رلهٔ plaintext از نداشتنِ رله بدتر است،
چون کلِ موضوع این است که کسی بایت‌ها را نبیند.

### چه چیزی عمداً تغییر نکرد

ردیف‌هایِ هشت شبکهٔ قدیمی‌تر (اتریوم، BSC، Polygon، Arbitrum، Base، Optimism،
Avalanche، Linea) **دست‌نخورده ماندند** — گزارش دربارهٔ آن‌ها نبود و دست زدن به
قولی که کاربر می‌گوید «دارم و کار می‌کند» خارج از این تغییر است. (نکته برای
پیگیری: برچسبِ «dRPC MEV-Protected» روی Optimism/Avalanche/Linea هم با همان
مستنداتِ بالا قابل تأیید نیست و باید در تغییری جدا بررسی شود.)

## ۴) سواپ بدون گس

### علت ریشه‌ای: کلاینت و سرور از هم جدا افتاده بودند

این یکی ساده‌ترین اشکال و در عین حال کامل‌ترین «هیچی نشان داده نمی‌شد» بود:

```js
// server/gasless.js  — حاضر:
const SUPPORTED = new Set([1,10,56,137,8453,42161,43114, 5000,143,4663,534352, 324]);

// src/lib/gasless.js — نپرسیده:
export const GASLESS_CHAINS = new Set([1, 10, 56, 137, 8453, 42161, 43114]);
```

سرور می‌پذیرفت، کلاینت هرگز دکمه را رندر نمی‌کرد. کاربری که روی Mantle فقط USDT
داشت و یک بایت MNT نداشت، صفحه‌ای مرده می‌دید — بی‌هیچ توضیحی.

### چه شد: بازسازیِ هر دو از جدولِ رسمیِ 0x

منبع: `docs.0x.org/docs/introduction/supported-chains`، خوانده‌شده در
۲۰۲۶-۱۰-۰۳. سطرهایی که ستونِ **Gasless** جلویشان ✅ دارد، تلاقی با رجیستریِ ما:

```
۱ Ethereum · ۱۰ OP Mainnet · ۵۶ BNB · ۱۳۷ Polygon · ۸۴۵۳ Base ·
۴۲۱۶۱ Arbitrum · ۴۳۱۱۴ Avalanche · ۱۴۶ Sonic · ۵۰۰۰ Mantle ·
۸۰۰۹۴ Berachain · ۱۳۰ Unichain · ۱۴۳ Monad · ۵۳۴۳۵۲ Scroll ·
۴۶۶۳ Robinhood Chain
```

دو استثنا، هر دو **عمدی**:

| شبکه | چرا نه | پیامی که کاربر می‌بیند |
|---|---|---|
| **zkSync Era (۳۲۴)** | 0x اصلاً ردیفی برای zkSync ندارد — نه Swap، نه Gasless. (کامنتِ قدیمیِ سرور خلافِ این را ادعا می‌کرد.) | `swap.gaslessChainOff.noZeroXChain` |
| **Linea (۵۹۱۴۴)** | 0x سواپ‌های Linea را مسیریابی می‌کند، ولی ستونِ Gasless جلویش خالی است. | `swap.gaslessChainOff.noZeroXGasless` |

چرا حذف‌شان درست است: گذاشتنِ یک زنجیره در این فهرست فقط یک سوییچ می‌خرد که هر
درخواستش `UNSUPPORTED_CHAIN` می‌گیرد — همان شکستی که `getGaslessStatus()`
اصلاً برای پیشگیری از آن وجود دارد. و حالا **دلیلش هم گفته می‌شود**: در
`src/pages/Swap.jsx`، اگر کاربر متصل باشد و موجودیِ سکهٔ بومی صفر، جملهٔ مربوط
چاپ می‌شود. قبلاً چون `gaslessEligible()` برای این دو `false` بود، نه سوییچی بود
و نه توضیحی — سکوتِ محض.

فایل‌ها: `src/lib/gasless.js` (`GASLESS_CHAINS` + `GASLESS_EXCLUDED` +
`gaslessExclusionReason`)، `server/gasless.js` (`SUPPORTED`)،
`server/providerStatus.js` (ردیف‌های `0x-gasless` و `0x-cross-chain`)،
`src/pages/Swap.jsx` (شاخهٔ توضیح)، و ۲ کلیدِ تازه در `en`/`fa`.

> نکتهٔ جانبی: فهرستِ `0x-cross-chain` در `providerStatus.js` هم از همان جدول
> به‌روز شد (Relay همهٔ زنجیره‌های جدول را پوشش می‌دهد؛ zkSync باز هم نیست).
> `server/xchain.js` allowlistِ خودش را ندارد، پس این ردیف صرفاً گزارش است.

## ۵) آزمون

`test/network-capability-parity-probe.mjs` — **۱۵۸ بررسی**، بدون شبکه، و در
`npm test` ثبت شد. چیزی که قفل می‌کند:

1. **تحلیل توکن:** هر ۱۶ زنجیرهٔ رجیستری در هر سه نگاشتِ GoPlus هست (کلاینت +
   دو فایلِ سرور)، و گزارشِ ارائه‌دهنده کمتر از آن را نشان نمی‌دهد.
2. **سواپ بدون گس:** مجموعهٔ کلاینت و سرور **دقیقاً برابرند** (هیچ زنجیره‌ای که
   یکی بدهد و دیگری رد کند)، هفت شبکهٔ جدید در هر دو هستند، دو استثنا در هیچ‌کدام
   نیستند و هر دو دلیلِ قابلِ چاپ دارند.
3. **MEV:** هر زنجیره مدلِ ممپول دارد؛ پنج زنجیرهٔ سِکوئِنسِر/رمزنگاری‌شده مسیری
   با `kind` درست عرضه می‌کنند؛ سه لایه‌یکِ با ممپولِ عمومی ادعای رله نمی‌کنند؛
   هاستِ جعلیِ `robinhood-rpc.publicnode.com` در کدِ اجرایی نیست
   (بررسی روی متنِ **بدون کامنت**، وگرنه در کامنتی که حذفش را توضیح می‌دهد پیدا
   می‌شد)؛ `relayOverride` فقط `https` می‌پذیرد؛ تعدیلِ ریسک روی زنجیرهٔ
   خصوصی کمتر از عمومی است و عددِ خام را حفظ می‌کند.
4. **هشت شبکهٔ گزارش، سرتاسری:** هر کدام باید اسکنِ هوش مصنوعی + مدلِ MEV +
   (گس‌لس یا دلیلِ مکتوبِ نبودش) را داشته باشند.

اجرا:

```bash
node test/network-capability-parity-probe.mjs   # ۱۵۸/۱۵۸
npm test                                        # شاملِ همان probe
```

## ۶) محدودیتِ صادقانهٔ این تغییر

- `node_modules` در این محیط نصب نبود و شبکهٔ sandbox بسته است؛ پس
  `npm test` / `vitest` / `vite build` اجرا نشدند. آنچه اجرا شد: probe جدید
  (۱۵۸/۱۵۸)، `node --check` روی فایل‌های تغییرکردهٔ سرور/کلاینت، و بازسنجیِ
  `src/i18n/coverage.json` با همان الگوریتمِ `scripts/gen-locales.mjs`.
- آزمونِ زندهٔ GoPlus روی هشت شبکه (اینکه برای **یک توکن واقعی** روی هر کدام
  داده برمی‌گردد، نه فقط اینکه `chainId` پذیرفته می‌شود) در این محیط ممکن نبود.
  پس از استقرار، برای یکی دو توکنِ پُرنقدشندگی روی هر شبکه یک بار
  `GET /api/token-risk?chainId=…&address=…` را صدا بزنید.
- آزمونِ زندهٔ گس‌لس روی هفت شبکهٔ جدید نیازمندِ `ZEROX_API_KEY` است و باید روی
  دستگاهِ صاحبِ کلید اجرا شود (مسیر: `/api/gasless/price`).
- ادعاهایِ مربوط به ممپول در جدولِ `MEV_CHAIN_MODEL` از مستندات و اندازه‌گیری‌های
  عمومی گرفته شده و در کامنتِ هر ردیف منبعش نوشته شده؛ اگر شبکه‌ای مدلش را عوض
  کرد (مثلاً سِکوئِنسِر غیرمتمرکز شد)، آن ردیف باید به‌روز شود.
