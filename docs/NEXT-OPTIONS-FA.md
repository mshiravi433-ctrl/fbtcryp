# چه چیزی می‌شود اضافه کرد — بررسی عمیق

تاریخ: ۲۰۲۶/۰۸/۰۷ · هر ادعای این سند **زنده تست شده**، نه از روی کد حدس زده

خواستی عمیق فکر کنم و ببینم چه گزینه‌ای می‌شود اضافه کرد. روش کارم این بود:
**به‌جای اینکه ایدهٔ جدید بسازم، اول شمردم چه چیزی از قبل ساخته شده و کاربر
نمی‌تواند به آن برسد.**

نتیجه غافلگیرکننده بود.

---

# 🔴 یافتهٔ اصلی: بزرگ‌ترین قابلیت ما دکمه ندارد

## سواپ بدون گس (Gasless) — کامل، تست‌شده، درآمدزا، و **غیرقابل‌دسترس**

این را با شمردن مصرف‌کننده‌ها پیدا کردم، نه با خواندن کد:

| بخش | وضعیت |
|---|---|
| سرور `server/gasless.js` | ✅ ۲۴۵ خط، کامل |
| چهار مسیر API | ✅ `status`, `price`, `quote`, `submit` |
| کلید 0x | ✅ فعال در ورسل |
| کارمزد ۰٫۷۰٪ | ✅ زنده تست شد |
| **کتابخانهٔ کلاینت** | ❌ **وجود ندارد** |
| **صفحه یا دکمه** | ❌ **وجود ندارد** |

**مدرک زنده، همین الان از سایت خودمان** — ۱۰ USDC روی Base:

```json
"fees": {
  "integratorFee": { "amount": "70000", "type": "volume" },
  "gasFee":        { "amount": "17933", "type": "gas" }
}
```

`70000` از `10000000` یعنی **دقیقاً ۰٫۷۰٪ به کیف ما**. و آن `gasFee` هم از
**خود توکن** کم می‌شود، نه از اتریوم کاربر.

تنها جایی که کلمهٔ `gasless` در کل رابط کاربری پیدا کردم، **صفحهٔ Developers**
است — یعنی فهرست فنی API. هیچ کاربر عادی هرگز آنجا نمی‌رود.

### چرا این از هر ایدهٔ جدیدی مهم‌تر است

مشکلی که حل می‌کند، **بن‌بست شمارهٔ یک کریپتو** است:

> کسی که USDT روی BNB دارد ولی BNB ندارد، **هیچ کاری** در اپ ما نمی‌تواند
> بکند. نه سواپ، نه پل، هیچ. و برای خریدن BNB هم به BNB نیاز دارد.

این دقیقاً همان کسی است که ما دنبالش هستیم: کسی که برایش تتر فرستاده‌اند و
در عمرش BNB نداشته. **او الان وارد اپ می‌شود و دست خالی برمی‌گردد.**

و توجه کن: این هم‌زمان با مشکل تازهٔ خودت است — «۰٫۰۲ دلار نداشتم». همان
دیوار.

### چقدر کار دارد

کد سرور نوشته شده. فقط `src/lib/gasless.js` و یک حالت در صفحهٔ سواپ لازم است.
**تخمین: یک جلسه.** صفر دلار، صفر ثبت‌نام.

> 💰 **درآمد:** ۰٫۷۰٪ روی معاملاتی که **امروز اصلاً اتفاق نمی‌افتند**، چون
> کاربر نمی‌تواند شروع کند.

## و همین الگو در چهار جای دیگر هم هست

تعداد فایل‌های رابط کاربری که هر API را صدا می‌زنند شمردم (بدون Developers):

| API | مصرف‌کنندهٔ UI | وضعیت |
|---|---|---|
| `/api/gasless/*` | **۰** | 🔴 بالا توضیح دادم |
| `/api/xchain/*` (پل ۰x، تنها راه **ترون**) | **۰** | 🔴 ترون در اپ غیرقابل‌دسترس است |
| `/api/dln/*` (deBridge) | ۰ مستقیم | 🟡 از طریق `lib/dln.js` وصل است ✓ |
| `/api/nft/*` | **۰** | 🟡 صفحهٔ NFT دارد ولی مسیر دیگری می‌رود |
| `/api/thor/*` | ۰ مستقیم | 🟡 از طریق `lib/thorchain.js` ✓ |

**ترون مهم است.** بخش بزرگی از کاربران ایرانی USDT را روی **TRC-20** نگه
می‌دارند چون کارمزدش کم است. سرور `xchain.js` (۳۶۸ خط) تنها راه رسیدن به
ترون است و **هیچ صفحه‌ای به آن وصل نیست**.

# 🟢 پیشنهاد من — به همین ترتیب

## ۱. سواپ بدون گس را وصل کن ⭐ **بالاترین اولویت**

بالا توضیح دادم. کد آماده، درآمد ثابت‌شده، بن‌بست اصلی را باز می‌کند.

## ۲. ترون را وصل کن

`server/xchain.js` آماده است. یک نکتهٔ اندازه‌گیری‌شده که باید در UI بیاید:

> **تلهٔ ۱۷ درصدی:** ۱۰ USDC از EVM به ترون → ۸٫۲۹ USDT.
> سهم ما ۰٫۳۰٪ است؛ بقیه‌اش هزینهٔ **فعال‌سازی حساب ترون** است که تقریباً
> **ثابت** است. روی ۱۰ دلار فاجعه است، روی ۱٬۰۰۰ دلار ناچیز.

سرور از قبل `lossPercent` و `severeLoss` را حساب می‌کند — دقیقاً مثل هشدار
کارمزد ثابت deBridge که همین امروز ساختم. فقط باید نشان داده شود.

> ⚠️ و یادآوری: **۰x روی مبدأ ترون کارمزد نمی‌دهد** (تست شده، خطای ۴۰۰).
> ترون فقط به‌عنوان **مقصد** درآمد دارد.

## ۳. سفارش‌های خودکار — محدودیتش را صادقانه بگو

`src/lib/orders.js` پنج نوع سفارش دارد: `limit`، `dca`، `trailing`،
`bracket`، `ladder`. کد کامل است.

**ولی همه‌شان فقط وقتی اپ باز است کار می‌کنند.** بدون سرور اجراکننده، یک
سفارش «فروش در ۱۰۰ هزار دلار» وقتی گوشی در جیب است اجرا نمی‌شود.

این همان محدودیتی است که برای هشدار قیمت هم داشتیم. **پیشنهاد نمی‌کنم کد
جدید بنویسیم — پیشنهاد می‌کنم در خود صفحه بنویسیم که این‌طور است.** کاربری
که فکر کند سفارشش شب اجرا می‌شود و نشود، ضرر واقعی می‌کند.

# ⚪ چیزهایی که **پیشنهاد نمی‌کنم**

صادق باشم دربارهٔ چیزهایی که وسوسه‌انگیزند ولی اشتباه‌اند:

| ایده | چرا نه |
|---|---|
| قابلیت جدید (چت، شبکهٔ اجتماعی، بازی) | پنج قابلیت **ساخته‌شده** داریم که دکمه ندارند. ساختن ششمی قبل از وصل کردن آن پنج‌تا، همان الگوی «wired to nothing» است که سه بار در این پروژه تکرار شده. |
| صرافی‌های بیشتر | ۱۷ خط درآمدی داریم، ۹ تا زنده. مشکل تعداد نیست. |
| توکن یا NFT خودمان | نیاز به سرمایه و نقدشوندگی دارد. و ما «پول نداریم». |
| اجرای سفارش سمت سرور | کرون ورسل روی پلن رایگان محدود است، و نگه داشتن کلید کاربر روی سرور یعنی **امانی شدن** — یعنی از بین رفتن کل مدل غیرامانی ما. |

## آنچه در همین جلسه انجام شد

پیش از این تحلیل، سه چیز دیگر هم ساخته شد:

**تنظیمات سواپ:**
- **لغزش خودکار** — از روی تأثیر قیمتی همان جفت حساب می‌شود. مشکل اصلی این
  نبود که ۰٫۵٪ پیش‌فرض بد است؛ این بود که ۳٪ که کاربر برای یک توکن کم‌عمق
  می‌گذاشت، **روی سواپ تتر بعدی‌اش هم می‌ماند** و آنجا پول مفت برای ربات
  ساندویچ است.
- **مهلت تراکنش** — پارامترش از اول وجود داشت و **هیچ‌وقت پاس داده نمی‌شد**؛
  هر سواپ این اپ روی ۲۰ دقیقهٔ ثابت بود.
- **«مقایسه شد با N منبع»** — کد کامنت داشت که «این خط را در UI نشان می‌دهد»
  و **هیچ خطی وجود نداشت**. سه اگریگیتور روی هر کلید صدا زده می‌شدند و
  نتیجه دور ریخته می‌شد.

**صفحهٔ P2P:** بخش خرید نقدی توضیح می‌داد چرا میز نداریم، سه میز فهرست
می‌کرد، چهار روش کلاهبرداری می‌گفت — و **هرگز نمی‌گفت چطور خرید کنی**. شش
مرحلهٔ واقعی اضافه شد، هشدارها در یک جعبهٔ بازشونده جمع شدند، و حالت
**اسکناس حضوری** که اصلاً پوششی نداشت اضافه شد.
