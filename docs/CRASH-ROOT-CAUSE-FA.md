## علت واقعی

در فایل `src/lib/verdict.js` این امضا نوشته شده بود:

```js
export function verdict({ analysis, series = [], btcSeries = [], coin = {} })
```

`coin = {}` **بی‌خطر به نظر می‌رسد و نیست.** در جاوااسکریپت مقدار پیش‌فرض
**فقط برای `undefined`** فعال می‌شود، نه برای `null`. پس اگر کسی `null`
بفرستد، مقدار پیش‌فرض رد می‌شود و کد روی `null` عملیات انجام می‌دهد → کرش.

### چرا دقیقاً بار اول کرش می‌کند

وقتی مستقیم یک کوین را باز می‌کنید، **سه درخواست هم‌زمان** می‌روند:

| درخواست | چه می‌آورد |
|---|---|
| `useCoin(id)` | خودِ اطلاعات کوین |
| `useChart(id)` | نمودار |
| `useMarkets(60)` | فهرست بازار |

نمودار **سبک‌تر** است و معمولاً **زودتر** می‌رسد. آن لحظه:

- `loading = false` (نمودار آمده)
- `coin = null` (هنوز نرسیده)
- شرط «ارز پیدا نشد» فعال نمی‌شود، چون درخواست کوین هنوز در حال اجراست
- صفحه `<VerdictPanel coin={null}>` را رندر می‌کند → **کرش**

### چرا بار دوم درست است

`getCoin` نتیجه را کش می‌کند. بار دوم کوین **از همان اولین رندر** موجود است،
پس آن حالت میانی اصلاً پیش نمی‌آید.

### چرا بعد از برگشتن دوباره کرش می‌کند

همان مسابقهٔ سرد دوباره تکرار می‌شود. **دقیقاً همان چیزی که گزارش دادید.**

## ۴. توکن RWA — **قابل دسترسی نبود، نه بی‌درآمد**

گفتید «الان توکن rwa هم نمیشه درامد زایی کرد». بررسی کردم — و **حق با شما بود**،
ولی دلیلش آن چیزی نبود که فکر می‌کردم.

توکن‌ها **درست ثبت شده بودند و کارمزد هم می‌دادند** (تست زنده تأیید کرد).
مشکل این بود که **هیچ لینکی به آن‌ها نمی‌رسید.**

هر لینک به این شکل است:
```
/swap?chain=1&from=USDT&to=PAXG
```

ولی بخشی از کد که `to=PAXG` را می‌خواند، **پارامتر `chain=1` را نادیده
می‌گرفت**. آن بخش توکن را در فهرست **شبکهٔ فعلی** می‌گشت — و PAXG فقط روی
اتریوم است. اگر کیف‌پول روی BNB بود، چیزی پیدا نمی‌شد و **بی‌صدا شکست می‌خورد**.

نکتهٔ جالب: بخش دیگری از همان فایل که با **آدرس قرارداد** کار می‌کند، این را
از قبل درست انجام می‌داد. فقط بخش **نماد** هرگز همان رفتار را نگرفته بود.

و همین ایراد **لینک‌های استیکینگ فارم** را هم که جلسهٔ قبل اضافه کردم بی‌صدا
خراب کرده بود.

تست بعد از اصلاح:
```
pax-gold        → /swap?chain=1&from=USDT&to=PAXG   ✓
tether-gold     → /swap?chain=1&from=USDT&to=XAUt   ✓
staked-ether    → /swap?chain=1&from=USDT&to=stETH  ✓
rocket-pool-eth → /swap?chain=1&from=USDT&to=rETH   ✓
```

## ۳. هیدر در دسکتاپ و لپ‌تاپ

همه‌چیز در هیدر مقدار **ثابتِ اندازهٔ گوشی** بود — نام برند ۱۵ پیکسل، نشان
۳۰ پیکسل، دکمه‌ها ۳۴ پیکسل — در حالی که ستون محتوا از ۵۲۰ به ۷۶۰ پیکسل
بزرگ شده بود. کنار آن، و از فاصلهٔ دسکتاپ (که از فاصلهٔ گوشی بیشتر است)،

## ۱. جعبه‌های انتخاب — «بسیار ساده»

کادر دور `<select>` از قبل تم‌دار بود، ولی **خودِ کنترل داخلش نه.**

بدون `appearance: none` مرورگر ظاهر خودش را نگه می‌دارد: فِلِش خاکستری
سیستمی در کروم، و یک کنترل کاملاً برجستهٔ قدیمی در فایرفاکس و سافاری دسکتاپ —
داخل کادر تیره و گرد ما. روی گوشی ناهماهنگی کوچکی است؛ روی دسکتاپ یک فرم
دههٔ ۹۰ چسبیده وسط کارت مدرن، که **دقیقاً همان «بسیار ساده»ای است که دیدید.**

اصلاح:
- ظاهر پیش‌فرض مرورگر حذف شد
- فِلِش خودمان به‌صورت SVG کشیده شد
- **برای راست‌به‌چپ فِلِش به سمت چپ می‌رود**
- نسخهٔ جدا برای تم روشن (فِلِش تیره روی سفید دیده نمی‌شد)
- فهرست باز شده هم در تم تیره، تیره است نه سفیدِ چشم‌زن

⚠️ یک محدودیت را صادقانه بگویم: **فهرست بازشده را سیستم‌عامل می‌کشد**، نه ما.
CSS فقط می‌تواند رنگ‌هایش را تا حدی تغییر دهد. اگر ظاهر کاملاً سفارشی بخواهید،
باید یک منوی دلخواه بسازیم که با صفحه‌کلید و صفحه‌خوان هم کار کند — کار
بزرگ‌تری است؛ بگویید تا انجام دهم.
