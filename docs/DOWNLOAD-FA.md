## ⚠️ این فایل روی Google Play نمی‌رود

باید صریح بگویم چرا، چون این تنها مانع باقی‌مانده است.

فایل فعلی **debug-signed** است — یعنی با یک کلید موقت که خود اندروید تولید
می‌کند امضا شده. برای تست روی گوشی خودت و دست دوستانت عالی است. اما گوگل پلی
دو چیز را قبول نمی‌کند:

۱. **امضای دیباگ.** پلی فقط اپی را می‌پذیرد که با کلید خودت امضا شده باشد.
۲. **فرمت APK.** برای اپ جدید فقط `.aab` قبول می‌کند.

کد و اسکریپت بیلد هر دو آماده‌اند — اسکریپت به‌محض دیدن کلید، هم APK و هم AAB
می‌سازد. **تنها چیزی که کم است، کلید امضاست، و آن را فقط تو می‌توانی بسازی.**

اگر من کلید را بسازم، من کلید هویت اپ تو را در اختیار دارم. این دقیقاً مثل
دادن عبارت بازیابی کیف پول است — یک مرزی است که نباید رد شود، حتی برای راحتی.

## ساخت نسخه قابل انتشار (۱۰ دقیقه، با گوشی)

### گام ۱ — کلید امضا

Termux را از **F-Droid** نصب کن (نسخه Play Store قدیمی است و کار نمی‌کند):

```bash
pkg update -y && pkg install openjdk-17 -y
mkdir -p ~/fbt && cd ~/fbt

keytool -genkeypair -v \
  -keystore fbt-release.keystore \
  -alias fbt \
  -keyalg RSA -keysize 2048 -validity 10950 \
  -dname "CN=FBT Swap, OU=Mobile, O=Fanous Bazaar Pishgam, L=Isfahan, ST=Isfahan, C=IR"
```

دو بار رمز می‌پرسد. **یک رمز قوی بساز و روی کاغذ بنویس.**

بعد:

```bash
base64 -w 0 fbt-release.keystore > ks.txt
cat ks.txt
```

رشته بلند را کپی کن.

> **مهم‌ترین جمله این سند:** فایل `fbt-release.keystore` را در **دو جای جدا**
> پشتیبان بگیر. گوگل لیست اپ تو را برای همیشه به این کلید گره می‌زند. اگر گمش
> کنی نمی‌توانی اپ خودت را آپدیت کنی — باید لیست جدید با نام پکیج جدید بسازی
> و همه نصب‌های قبلی یتیم می‌شوند.

### گام ۲ — چهار Secret در گیت‌هاب

`Settings → Secrets and variables → Actions → New repository secret`

| Name | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | محتوای `ks.txt` |
| `ANDROID_KEYSTORE_PASSWORD` | رمزی که ساختی |
| `ANDROID_KEY_ALIAS` | `fbt` |
| `ANDROID_KEY_PASSWORD` | همان رمز |

### گام ۳ — دو Variable

همان صفحه، تب **Variables**:

| Name | Value |
|---|---|
| `VITE_API_BASE` | `https://<اپ-ورسل-تو>.vercel.app/api` |
| `APP_VERSION_CODE` | `1` |

`VITE_API_BASE` مهم است: اپ اندروید صفحاتش را از `https://localhost` سرو
می‌کند، پس مسیر نسبی `/api` به هیچ‌جا نمی‌رسد و اخبار و رتبه‌بندی کار نمی‌کنند.

برای هر انتشار بعدی `APP_VERSION_CODE` را یکی زیاد کن — گوگل آپلودی که شماره‌اش
بالاتر نباشد را رد می‌کند.

### گام ۴ — بیلد

`Actions → Build APK → Run workflow`

حدود ۳ دقیقه. حالا در Artifacts دو فایل داری:

| فایل | کجا |
|---|---|
| `app-release.aab` | **← این را در Google Play آپلود کن** |
| `app-release.apk` | نصب مستقیم، کافه‌بازار، مایکت |

### گام ۵ — Play Console

<https://play.google.com/console> — ۲۵ دلار یک‌بار.

| فیلد | مقدار |
|---|---|
| App name | FBT Swap |
| Package | `ir.fbt.swap` (از قبل تنظیم شده) |
| Developer | Fanous Bazaar Pishgam |
| Country | Iran |
| Category | Finance |
| Website | `https://<اپ-تو>.vercel.app` |
| Privacy policy | `https://<اپ-تو>.vercel.app/#/legal/privacy` |

**Data safety:** نام و ایمیل و تلفن و مکان جمع نمی‌شود. فقط آدرس کیف پول
(اختیاری) و نام نمایشی (اختیاری). عبارت بازیابی هرگز از دستگاه خارج نمی‌شود.

**اول Internal testing، نه Production.** بازبینی سریع‌تر است و اگر ایرادی
باشد لیست عمومی‌ات را خراب نمی‌کند.

## آنچه در این نوبت درست شد

### منوی «بیشتر» — علت واقعی تکان خوردن

نوبت قبل دو باگ واقعی را رفع کردم، ولی هیچ‌کدام آن چیزی نبود که تو حس
می‌کردی. این بار شمردم:

باز شدن منو حدود **۹۰ انیمیشن هم‌زمان** شروع می‌کرد — ۱۸ کاشی، هر کدام یک
spring برای دکمه، یک spring برای آیکون، و ۲ تا ۴ مسیر SVG متحرک. همه اینها
داخل پنلی که خودش `scale` می‌شد.

دو دلیل که این را بد می‌کند نه فقط سنگین:

- انیمیت کردن `scale` روی والد، مرورگر را مجبور می‌کند هر فریم تمام فرزندها را
  دوباره رسترایز کند. با ۱۸ تا `clip-path` زیرش، گران است.
- `pathLength` روی کامپوزیتور اجرا نمی‌شود. هر قدمش روی ترد اصلی است و دقیقاً
  با کار رندر React در همان فریم‌ها رقابت می‌کند.

حالا: پنل فقط `opacity` و `y` را انیمیت می‌کند (بدون `scale`)، کاشی‌ها به‌جای
۱۸ spring مجزا با ۳ انیمیشن CSS گروهی محو می‌شوند، و آیکون‌ها موقع باز شدن
ساکن‌اند و فقط هنگام لمس حرکت می‌کنند.

به‌نظرم این طراحی بهتری هم هست: منویی که با ۱۸ کاشی جداگانه منفجر می‌شود
شلوغ است، نه جذاب.

### «از هوش مصنوعی بپرس» حذف شد

حق با تو بود. یک چت‌باکس در اپ کیف پول قولی می‌دهد که نمی‌تواند به آن عمل
کند: «هر چیزی بپرس و جواب قابل اعتماد بگیر — درباره پولت».

سه مشکل داشت: بدون مدل تنظیم‌شده از یک پایگاه دانش ثابت جواب می‌داد ولی
هنوز **شبیه چت‌بات** بود؛ با مدل، می‌توانست کارمزد یا مسیر بازیابی از خودش
دربیاورد و کسی که به مسیر بازیابی ساختگی عمل کند پولش را از دست می‌دهد؛ و در
هر دو حالت کاربر باید **سوال درست را حدس می‌زد**.

پایگاه دانش همیشه بخش صادقانه ماجرا بود: دوازده جواب دست‌نویس درباره همین
اپ، که با کد تطبیق داده شده‌اند. حالا خودِ آن کل قابلیت است:

- **سوالات متداول** به‌صورت آکاردئون — همه سوال‌ها یکجا دیده می‌شوند
- دکمه بزرگ **«راهنمای گام‌به‌گام را ببین»** بالای صفحه
- اگر جواب نبود → **تماس با پشتیبانی**

آفلاین کار می‌کند، چیزی از خودش درنمی‌آورد، و لازم نیست سوال درست را حدس بزنی.

سوال‌ها برای هر ۱۲ زبان ترجمه شدند. جواب‌ها فارسی/انگلیسی/عربی‌اند و بقیه
زبان‌ها به انگلیسی برمی‌گردند — این عمدی است: این جواب‌ها درباره تراکنش
برگشت‌ناپذیر و عبارت بازیابی گم‌شده‌اند، و یک ترجمه ماشینی با لحن مطمئن ولی
غلط، بدتر از متنی است که خواننده می‌فهمد به زبان او نیست.
