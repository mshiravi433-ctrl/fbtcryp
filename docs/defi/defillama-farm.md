# اتصال DefiLlama در Farm

## دامنهٔ اجرا

DefiLlama منبع دادهٔ عمومی و بدون کلید API است، نه قرارداد واریز، برداشت یا claim. این اتصال برای دریافت، کشف، فیلتر، تحلیل و تاریخچهٔ استخرها اجرایی است. مسیرهای تراکنش Aave، Compound و Lido همچنان آداپتور، پرچم فعال‌سازی، سقف مبلغ و تأیید کیف پول خودشان را دارند. این تغییر هیچ پرچم تراکنش را فعال نمی‌کند و هیچ تراکنشی ارسال نمی‌کند.

## مسیر داده

- `GET /api/yields`: دریافت از `https://yields.llama.fi/pools`؛ همان فیلترهای پروتکل و شبکه، حداقل TVL پنج میلیون دلار، APY بین ۰٫۵ تا ۶۰ درصد و فیلتر outlier/emissions حفظ شده‌اند.
- حداکثر ۵۰۰ ردیف رتبه‌بندی‌شده، بدون شناسهٔ تکراری، به مرورگر می‌رسد. `considered` تعداد ورودی، `passed` تعداد قبول‌شده و `truncated` محدودشدن خروجی را نشان می‌دهند. تب استخرها در هر مرحله ۲۴ کارت نمایش می‌دهد.
- `GET /api/yields/:id/history`: UUID معتبر و عضویت در فهرست فیلترشده بررسی می‌شود؛ سپس `/chart/:id` از میزبان ثابت DefiLlama فراخوانی می‌شود. این مسیر پراکسی URL دلخواه نیست.
- تاریخچه حداکثر ۳۶۵ مشاهدهٔ روزانه دارد؛ برای هر روز جدیدترین مشاهده نگه داشته و نتیجه برحسب زمان مرتب می‌شود. نمودار بازه‌های ۳۰، ۹۰ و ۳۶۵ روز و معیارهای APY/TVL دارد. روزهای بدون داده جعل نمی‌شوند.
- `DefiLlamaYieldAdapter` بدون ورودی اولیه داده را از API برنامه دریافت می‌کند؛ متدهای getPool، getAPY، getAPR، getTVL و getHistory به دادهٔ واقعی وصل هستند. execute/prepare همچنان UNAVAILABLE هستند.

## کش و خطا

- کش درون‌حافظه‌ای هر instance یک ساعت است؛ درخواست‌های هم‌زمان برای یک منبع ادغام می‌شوند.
- در خطای upstream، فقط نسخهٔ کمتر از دو ساعت با `freshness: STALE` و زمان دریافت اصلی برگردانده می‌شود؛ وضعیت قدیمی هم در JSON و هم در هدر موجود است.
- پس از دو ساعت داده برگردانده نمی‌شود؛ پاسخ ۵۰۲ ساختاریافته است. صفحه نیز حتی اگر درخواست بعدی معلق بماند، دادهٔ منقضی را حذف می‌کند.
- خطاها ۳۰ ثانیه backoff دارند. پاسخ‌های API `Cache-Control: no-store` دارند تا CDN عمر داده را تمدید نکند. این هدر کش داخلی سرور را غیرفعال نمی‌کند.
- تعداد ورودی‌های کش و backoff محدود است. این کش پایدار یا سراسری بین instanceها نیست.
- به‌روزرسانی صفحه هر پنج دقیقه هنگام قابل مشاهده بودن، هنگام بازگشت/online و با دکمهٔ به‌روزرسانی انجام می‌شود. به‌روزرسانی دستی کش یک‌ساعتهٔ منبع را دور نمی‌زند.
- خروج از صفحه، درخواست قبلی را abort می‌کند. خطای تاریخچه، اطلاعات اصلی استخر را پنهان نمی‌کند و دکمهٔ تلاش دوباره دارد.
- `UPSTREAM_TIMEOUT_MS` اختیاری است: پیش‌فرض ۱۲ ثانیه، حداکثر ۳۰ ثانیه. مهلت کلاینت برای فهرست ۳۵ ثانیه و برای تاریخچه ۶۵ ثانیه است تا در کش سرد، بررسی فهرست و دریافت تاریخچه هر دو فرصت کامل داشته باشند.

## معنای اعداد

- null، مقدار خالی و مقدار غیرعددی «ناموجود» هستند، نه صفر.
- APY و apyBase، APR نیستند. APR فقط در صورت وجود فیلد صریح نمایش داده می‌شود؛ خروجی فعلی عمومی معمولاً آن را ندارد.
- هزینهٔ gas یا پروتکلِ نامعلوم، صفر محسوب نمی‌شود؛ تخمین بازده خالص کامل در این وضعیت موجود نیست. عدد «قبل از گس» صریحاً همین نام را دارد و برآورد است، نه quote اجرایی.
- `at`/`updatedAt` زمان دریافت داده است، نه تضمین زمان محاسبهٔ نرخ توسط پروتکل. timestamp تاریخچه زمان مشاهدهٔ upstream است.
- فیلتر و امتیاز ریسک تضمین امنیت، سود یا امکان برداشت نیستند.

## آزمون

```sh
npm run test:farm
NODE_OPTIONS=--max-old-space-size=3072 npm run build
npm run test:farm:live
```

`test:farm` مرز شبکه را با fixture جایگزین می‌کند، نه منطق برنامه را: نرمال‌سازی، فیلترها، کش و stale/expiry، هم‌زمانی، مسیر HTTP واقعی، لغو درخواست، محاسبات، نمایش فارسی/انگلیسی، بازیابی خطا، فیلتر/صفحه‌بندی و بازشدن جزئیات از تب‌های بازار و استراتژی تست می‌شوند.

`test:farm:live` هیچ mock یا تراکنشی ندارد و باید در محیط دارای دسترسی خروجی HTTPS به `yields.llama.fi` اجرا شود. قطع شبکه باید آن را fail کند، نه اینکه با دادهٔ نمایشی موفق شود.

### نتیجهٔ محیط توسعه در ۲۰۲۶-۰۹-۰۸

- تست‌های فارم و build تولیدی موفق بودند. build در این محیط به افزایش heap Node به ۳ گیگابایت نیاز داشت.
- ممیزی wiring و مجموعهٔ unit موجود نیز موفق بودند.
- سرور کامل روی پورت ۸۷۸۷ راه‌اندازی شد؛ `/farm` پاسخ ۲۰۰، شناسهٔ تاریخچهٔ نامعتبر پاسخ ۴۰۰ و قطع upstream پاسخ ۵۰۲ با `no-store` دارد.
- درخواست مستقیم Node و curl به میزبان DefiLlama در مرحلهٔ TLS با ECONNRESET / SSL_ERROR_SYSCALL شکست خورد. بنابراین دریافت زنده در این محیط تأیید نشده است؛ تست live باید روی میزبان استقرار دوباره اجرا شود.
