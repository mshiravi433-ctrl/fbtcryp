# آنچه خروجی تو لو داد

این را فرستادی:

```json
"fcm":{"configured":false,"devices":0,"missing":[]}
```

به `missing` نگاه کن: **خالی است**. ولی `configured` هم `false` است.

منطق سرور را با همهٔ حالت‌های ممکن اجرا کردم. این ترکیب فقط در **یک** حالت ممکن است:

| حالت | خروجی |
|---|---|
| هیچ‌کدام ست نشده | `missing: ["FIREBASE_PROJECT_ID","FIREBASE_CLIENT_EMAIL","FIREBASE_PRIVATE_KEY"]` |
| هر سه ست، کلید درست | `configured: true` |
| **هر سه ست، ولی کلید خراب** | **`configured:false`, `missing:[]`** ← خروجی تو |

**یعنی هر سه متغیر FIREBASE را قبلاً ست کرده‌ای، ولی مقدار `FIREBASE_PRIVATE_KEY` غلط است.**

تقریباً با اطمینان می‌دانم چه شده: به‌جای `private_key`، مقدار `private_key_id` را
گذاشته‌ای. این دو در فایل JSON **درست بالای هم** هستند و اسمشان شبیه است.
همان `dd3e2f8a...` که قبلاً در چت فرستادی، `private_key_id` بود.

`private_key_id` یک رشتهٔ هگز ۴۰ کاراکتری است. `private_key` یک متن چندخطی بلند است
که با `-----BEGIN PRIVATE KEY-----` شروع می‌شود.

> این را در سرور هم درست کردم: از این به بعد `/api/cron/status` مستقیم می‌گوید
> «کلید ست شده ولی هدر BEGIN ندارد، احتمالاً private_key_id را گذاشته‌ای» —
> به‌جای اینکه `missing: []` نشان بدهد و هیچ سرنخی ندهد.

**پس بخش ۳ را با دقت بخوان — همان جایی است که گیر کرده‌ای.**

**۴.** بالای صفحه چند تب هست. تب **Cloud Messaging** را بزن

**۵.** اسکرول کن پایین تا به بخش **Web Push certificates** برسی

**۶.** یک جدول با دو ستون می‌بینی: **Key pair** و **Private key**

> همان دو مقداری که قبلاً در چت فرستادی، از همین‌جا آمده بودند. بررسی‌شان کردم و
> فرمتشان کاملاً درست بود — پس جای درستی را نگاه کرده بودی.

### چون در چت لو رفته، یکی نو بساز

**۷.** کنار ردیف موجود یک **⋮** (سه‌نقطه) هست ← بزن ← **Delete**

**۸.** حالا دکمهٔ **Generate key pair** را بزن

یک جفت نو ساخته می‌شود. **این صفحه را باز نگه دار.**

### گذاشتن در ورسل

| Key | Value |
|---|---|
| `VITE_VAPID_PUBLIC_KEY` | مقدار ستون **Key pair** — رشتهٔ بلند ۸۷ کاراکتری که با `B` شروع می‌شود |
| `VAPID_PRIVATE_KEY` | مقدار ستون **Private key** — کوتاه‌تر، ۴۳ کاراکتر |
| `VAPID_SUBJECT` | `mailto:` بعلاوهٔ ایمیل خودت. مثلاً `mailto:mshiravi433@gmail.com` |

> ⚠️ **به `VAPID_PRIVATE_KEY` هرگز `VITE_` اضافه نکن.**
> هر متغیری که با `VITE_` شروع شود داخل فایل جاوااسکریپتی که همهٔ کاربران دانلود
> می‌کنند کامپایل می‌شود. با آن پیشوند، دیگر راز نیست — منتشر شده است.
>
> کلید **عمومی** عمداً `VITE_` دارد. آن یکی درست است.

# بخش ۳ — سه مقدار فایربیس ← **اینجا گیر کرده‌ای**

### هشدار

فایل سرویس‌اکانتی که قبلاً فرستادی **دسترسی کامل ادمین** به کل پروژه می‌دهد —
نه فقط نوتیفیکیشن. با آن می‌شود کل دیتابیس را خواند یا پاک کرد.
و برخلاف رمز، **«عوض کردن» ندارد؛ فقط حذف و ساخت نو.**

### پیدا کردن

**۱.** برو به `console.cloud.google.com/iam-admin/serviceaccounts`

**۲.** بالای صفحه یک انتخابگر پروژه هست. **`fbt-room-a46fc`** را انتخاب کن

**۳.** در لیست روی این بزن:
`firebase-adminsdk-fbsvc@fbt-room-a46fc.iam.gserviceaccount.com`

**۴.** تب **KEYS** را بزن

**۵.** کلیدی که با `dd3e2f8a` شروع می‌شود را پیدا کن ← **🗑 Delete** ← تأیید کن

**۶.** حالا **ADD KEY** ← **Create new key** ← نوع **JSON** ← **CREATE**

یک فایل `.json` در پوشهٔ Downloads گوشی‌ات دانلود می‌شود.

### باز کردن فایل

فایل را با یک ویرایشگر متن باز کن (اپ «Files» گوشی معمولاً می‌تواند).
محتوایش این شکلی است:

```json
{
  "type": "service_account",
  "project_id": "fbt-room-a46fc",
  "private_key_id": "dd3e2f8a0523ec5103df0d304abfff716e70d976",
  "private_key": "-----BEGIN PRIVATE KEY-----\nMIIEvQIBADANBgkqhkiG9w0BAQEFAASCBKcwggSjAgEAAoIBAQCs1Cmll2reCapg\n...چندین خط...\n-----END PRIVATE KEY-----\n",
  "client_email": "firebase-adminsdk-fbsvc@fbt-room-a46fc.iam.gserviceaccount.com",
  "client_id": "..."
}
```

### 🔴 اینجا همان جایی است که اشتباه شد

به دو خط پشت سر هم نگاه کن:

```
"private_key_id": "dd3e2f8a0523..."     ← ❌ این را لازم نداری
"private_key":    "-----BEGIN PRIV..."  ← ✅ این را می‌خواهی
```

اسمشان شبیه است و کنار هم‌اند. **مقدار درست آن است که با `-----BEGIN` شروع می‌شود
و خیلی بلند است** (چند خط، حدود ۱۷۰۰ کاراکتر). آن هگز ۴۰ کاراکتری کوتاه، غلط است.

### گذاشتن در ورسل

| Key | Value |
|---|---|
| `FIREBASE_PROJECT_ID` | `fbt-room-a46fc` |
| `FIREBASE_CLIENT_EMAIL` | مقدار `client_email` — کل آدرس ایمیل |
| `FIREBASE_PRIVATE_KEY` | مقدار `private_key` — **کل رشتهٔ بلند** |

**برای `FIREBASE_PRIVATE_KEY` دقیقاً این‌طور عمل کن:**

✅ از `-----BEGIN PRIVATE KEY-----` شروع کن، تا `-----END PRIVATE KEY-----\n` ادامه بده

✅ آن `\n`ها را **همان‌طور که هستند بگذار**. حذفشان نکن. به Enter تبدیلشان نکن.
سرور خودش تبدیلشان می‌کند.

❌ گیومه‌های `"` اول و آخر را کپی نکن — فقط محتوای داخلشان

❌ `private_key_id` را نگذار

# چطور بفهمی کار کرد

این آدرس را باز کن:

```
https://www.lawpoetics.ir/api/cron/status
```

**باید این را ببینی:**

```json
{"web":{"configured":true,"subscribers":0,"missing":[]},
 "fcm":{"configured":true,"devices":0,"missing":[]},
 "cronSecretSet":true,"durableStorage":true,"canSend":false}
```

سه تا `true` مهم‌اند: `web.configured`، `fcm.configured`، `cronSecretSet`.

`subscribers` و `devices` هنوز صفرند و `canSend` هم `false` — **این طبیعی است.**
یعنی هنوز هیچ دستگاهی نوتیفیکیشن را روشن نکرده.

**تست نهایی:** در اپ برو تنظیمات ← نوتیفیکیشن ← روشن کن. بعد دوباره این آدرس را باز کن.
حالا `devices` باید `1` شود و `canSend` بشود `true`. آن لحظه یعنی کل زنجیره کار می‌کند.
