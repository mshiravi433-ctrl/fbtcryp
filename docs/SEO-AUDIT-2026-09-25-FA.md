# ممیزی محدود به سئو — FBT Swap — ۲۵ سپتامبر ۲۰۲۶

> دامنهٔ بررسی: فقط HTML عمومی، فایل‌های سئو، ژنراتور صفحات استاتیک، پیوندهای داخلی و آزمون خروجی. هیچ فایل `src/`، مسیر اپ، اتصال کیف‌پول، API، معامله یا رفتار React تغییر نکرده است. این گزارش ادعای رتبه، ترافیک یا ایندکس‌شدن ندارد.

## روش و محدودیت

- نسخهٔ عمومیِ قابل‌دریافتِ [`/robots.txt`](https://fbtswap.ir/robots.txt)، [`/sitemap.xml`](https://fbtswap.ir/sitemap.xml)، [صفحهٔ اصلی](https://fbtswap.ir/)، [لندینگ صرافی](https://fbtswap.ir/صرافی-غیرمتمرکز)، [راهنمای سواپ فارسی](https://fbtswap.ir/سواپ-ارز-دیجیتال)، [وبلاگ انگلیسی](https://fbtswap.ir/blog)، [`/llms.txt`](https://fbtswap.ir/llms.txt) و [`/ai/intent-os`](https://fbtswap.ir/ai/intent-os) خوانده شد. ابزار دریافت محتوای وب، سربرگ‌های HTTP یا گزارش Google Search Console را ارائه نمی‌کند؛ لذا وضعیت واقعی ریدایرکت‌ها، پوشش ایندکس و Core Web Vitals باید بعد از استقرار جداگانه سنجیده شود. تلاش برای دریافت سربرگ‌ها با `curl` در این محیط به خطای TLS خورد؛ از آن نتیجهٔ «در دسترس نبودن سایت برای خزنده‌ها» نمی‌گیریم.
- رجیستری فعلی `src/lib/chains.js` شامل ۱۶ زنجیرهٔ EVM است و مسیر Solana جداست: **۱۷ شبکه**. کد اپ فقط برای راستی‌آزمایی خوانده شد؛ تغییر نکرد.
- `npm run build` در همین شاخه **۲۱ صفحهٔ استاتیک + صفحهٔ اصلی** تولید می‌کند. آزمون جدید، وجود فایل HTML، یکتا بودن title/description، canonical، `og:url`، XML نقشه و پیوندهای دوزبانه را روی همان `dist/` بررسی می‌کند. این آزمون فقط خروجی محلی را اثبات می‌کند، نه خروجی استقرار فعلی.

## اصلاحات محدود این نوبت

1. نام/توضیح `WebPage` در JSON-LD صفحهٔ اصلی با عنوان و توضیحِ **۱۷ شبکه** هماهنگ شد؛ موجودیت سازمان به حساب عمومیِ از پیش معرفی‌شده پیوند داده شد.
2. `llms.txt` از ۱۴ به ۱۷ شبکه و فهرست واقعی به‌روز شد. «بدون احراز هویت» به **رابط سواپ روی زنجیره** محدود شد؛ نیازهای احتمالی کیف‌پول، پرداخت فیات یا پروتکل ثالث مستثنی است.
3. گروه‌های متناقض `robots.txt` حذف شدند؛ همهٔ خزنده‌ها مجاز به صفحات عمومی و ممنوع از `/api/` هستند؛ اشاره به sitemap حفظ شد.
4. `/blog` و `/وبلاگ` به‌صورت `hreflang` دوطرفه به هم معرفی شدند. در فوتر قابل‌دیدن لندینگ اصلی به هر دو هاب و راهنماهای موجود لینک افزوده شد؛ هیچ صفحهٔ موجود حذف نشد.
5. متن آمادهٔ معرفی در `docs/SEO-VISIBILITY-FA.md` نیز با ۱۷ شبکه یکسان شد. `npm run test:seo` برای جلوگیری از برگشت این مغایرت‌ها افزوده شد.

## اولویت‌های بعدی، **بدون تغییر اپ** (اجرا نشده)

- **P1، محتوای واقعی:** یک جفت صفحهٔ مستقل فارسی/انگلیسی برای Intent OS، سپس در صورت اثبات مسیر کاربری و محدودیت‌ها برای Cross-chain و Lending. هر صفحه باید پاسخ مسئله، نحوهٔ کارِ موجود، پیش‌نیازها، محدودیت منطقه/پروتکل، هزینه، ریسک و لینک مشخص به صفحهٔ واقعی اپ داشته باشد. تنها وجود یک route در React دلیل کافی برای ادعای «قابلیت فعال برای همه» نیست.
- **P1، اعتماد:** یک About/Trust عمومی، **فقط با اطلاعات قابل‌تأیید** دربارهٔ هویت، تماس، کارمزد و مدل امانت‌داری. بدون سند واقعی، عبارت «حسابرسی‌شده»، تیم نام‌برده، مجوز، rating یا review اضافه نشود. `parentOrganization` ساختگی برای همان شرکت هم لازم نیست.
- **P2، شبکه‌ها:** از Solana و یکی‌دو شبکهٔ دیگر با تفاوت عملیاتیِ واقعی شروع شود، نه ۱۷ متن قالبی. برای هر شبکه مسیر سواپ، کیف‌پول، هزینهٔ گس، محدودیت توکن و خطاهای رایج باید با کد و سرویس زنده تطبیق داده شود.
- **فعلاً نه:** تغییر URLهای فارسی موجود، ساخت صدها صفحهٔ توکن یا شبکه، تاریخ `lastmod` خودکار در هر build، sitemap index مصنوعی، یا وعدهٔ رتبهٔ اول. این‌ها می‌توانند به محتوای تکراری/غلط یا از دست رفتن URLهای شناخته‌شده منجر شوند.

## چک‌لیست انتشار

1. محلی: `npm run build && npm run test:seo && npm run test:landing`.
2. پس از انتشار روی **دامنهٔ اصلی**: محتوای `/robots.txt` و `/sitemap.xml` و چند نمونهٔ فارسی/انگلیسی را با URL Inspection بررسی کن. URLهای sitemap باید HTML همان صفحه، canonical خودشان و در صورت داشتن همتا `hreflang` دوطرفه داشته باشند؛ وضعیت HTTP، ریدایرکت و سربرگ‌ها را با ابزار قابل‌اعتماد در محیطی که به دامنه دسترسی دارد بسنج.
3. در Search Console وضعیت sitemap، Pages و Performance را مقایسه کن؛ IndexNow جایگزین تأیید ایندکس در گوگل نیست. این تغییرات فقط **پس از استقرار** روی دامنه اثر می‌گذارند.
