# از اینجا تا گوگل‌پلی — مرحله به مرحله

کلید امضا را ساخته‌ای، پس مرحله‌های ۱ تا ۳ اینجا فقط «وارد کردن» همان چیزی
است که ساخته‌ای. کل کار با گوشی انجام می‌شود.

هر مرحله را که تمام کردی، برگرد سراغ مرحله بعد. اگر جایی گیر کردی، بخش
«وقتی خطا دیدی» در انتها را بخوان.

---

## مرحله ۰ — اول این چهار رمز را باطل کن (۵ دقیقه)

این را اول می‌گویم چون بعداً یادت می‌رود و این‌ها همین حالا لو رفته‌اند. هر
چیزی که در چت فرستاده شود، لو رفته حساب می‌شود.

| کجا | کار |
|---|---|
| console.groq.com → API Keys | کلید `gsk_O0rYai...` را Delete کن، یک کلید تازه بساز |
| Vercel → Storage → Blob | توکن `vercel_blob_rw_FSVx...` را Reset کن |
| SignalWire → API | کلید `PSK_25twsi...` را حذف کن (این سرویس اصلاً به کار این اپ نمی‌آید) |
| حساب گوگلی که با آن Play Console می‌سازی | رمز `a09303653064A@` را عوض کن و ورود دومرحله‌ای را روشن کن |

آن حساب گوگل قرار است مالک اپ باشد. اگر کسی به آن دسترسی پیدا کند، اپ را از
دست می‌دهی — نه با هک کردن کد، فقط با وارد شدن به حساب.

---

## مرحله ۱ — فایل workflow را درست کن

**چرا اصلاً لازم است:** فایل فعلی `.github/workflows/build-apk.yml` دستور
`bash ci/build-apk.sh` را اجرا می‌کند ولی هیچ بلوک `env:` ندارد. گیت‌هاب
secretها را خودبه‌خود به اسکریپت نمی‌دهد — فقط از راه `env:` می‌دهد. پس داخل
اسکریپت این شرط:

```bash
if [ -n "${ANDROID_KEYSTORE_BASE64:-}" ]
```

همیشه نادرست است، و هر بار **بی‌سروصدا** نسخه debug ساخته می‌شود. حتی اگر هر
چهار secret را درست وارد کرده باشی. در لاگ هم هیچ خطایی نمی‌بینی — این
بدترین نوع باگ است، چون شکل «کلید امضا کار نمی‌کند» را دارد.

**چرا من انجامش نمی‌دهم:** گیت‌هاب به توکن ربات‌ها اجازه نوشتن در پوشه
`.github/workflows/` نمی‌دهد. این یک قانون امنیتی خود گیت‌هاب است، نه محدودیت
من. امتحان کردم و رد شد:

```
! [remote rejected] refusing to allow a GitHub App to create or update
  workflow .github/workflows/build-apk.yml without workflows permission
```

**کاری که تو می‌کنی:**

۱. این لینک را در مرورگر گوشی باز کن (متن آماده را کپی کن):

<https://raw.githubusercontent.com/mshiravi433-ctrl/fbtcryp/arena/019fa8cd-fbtcryp/ci/WORKFLOW-FIXED.yml>

۲. کل متن را انتخاب و کپی کن.

۳. حالا این لینک را باز کن (ویرایش فایل اصلی):

<https://github.com/mshiravi433-ctrl/fbtcryp/edit/arena/019fa8cd-fbtcryp/.github/workflows/build-apk.yml>

۴. همه محتوای قبلی را پاک کن، متن کپی‌شده را جای‌گذاری کن.

۵. پایین صفحه → **Commit changes** → گزینه «Commit directly to the
   `arena/019fa8cd-fbtcryp` branch» → **Commit changes**.

> ⚠️ حتماً روی برنچ `arena/019fa8cd-fbtcryp` کامیت کن، نه `main`. کد جدید
> روی این برنچ است.

## مرحله ۲ — چهار secret کلید امضا

مسیر: `Settings` → `Secrets and variables` → `Actions` → تب **Secrets** →
`New repository secret`

لینک مستقیم:
<https://github.com/mshiravi433-ctrl/fbtcryp/settings/secrets/actions>

| Name | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | رشته بلند base64 که اسکریپت ساخت کلید چاپ کرد |
| `ANDROID_KEYSTORE_PASSWORD` | رمز فایل keystore |
| `ANDROID_KEY_ALIAS` | `fbt` |
| `ANDROID_KEY_PASSWORD` | رمز کلید (اگر جدا انتخاب نکردی، همان رمز بالا) |

**دو نکته که معمولاً کار را خراب می‌کند:**

- رشته base64 باید **یک خط پیوسته** باشد، بدون شکستگی و بدون فاصله. اگر موقع
  کپی از ترموکس چند خط شد، در یک ویرایشگر متن خط‌ها را به هم بچسبان. یک
  «\n» اضافه وسط رشته یعنی فایل keystore خراب رمزگشایی می‌شود و بیلد با خطای
  نامفهوم `Invalid keystore format` می‌ایستد.
- نام‌ها را دقیقاً همین‌طور بنویس. حروف بزرگ و کوچک مهم است. `ANDROID_Key_Alias`
  کار نمی‌کند.

## مرحله ۳ — دو variable (این‌ها secret نیستند)

همان صفحه، ولی تب **Variables** → `New repository variable`

| Name | Value |
|---|---|
| `VITE_API_BASE` | `https://<اسم-پروژه-ورسل-تو>.vercel.app/api` |
| `APP_VERSION_CODE` | `1` |

**`VITE_API_BASE` را جدی بگیر.** اپ اندروید صفحاتش را از `https://localhost`
بارگذاری می‌کند. اگر این متغیر خالی باشد، اپ درخواست‌هایش را به
`https://localhost/api` می‌فرستد — یعنی به خود گوشی — و آنجا هیچ سروری نیست.
نتیجه: اپ باز می‌شود ولی قیمت‌ها هیچ‌وقت نمی‌آیند. این دقیقاً همان چیزی است که
یک بازبین گوگل می‌بیند و اپ را رد می‌کند.

`APP_VERSION_CODE` باید برای **هر آپلود جدید** یک عدد بیشتر شود. گوگل نسخه‌ای
با کد تکراری را قبول نمی‌کند. الان `1`، دفعه بعد `2`.

## مرحله ۴ — بیلد را اجرا کن

۱. برو به تب **Actions**:
   <https://github.com/mshiravi433-ctrl/fbtcryp/actions>
۲. از ستون چپ **Build APK** را انتخاب کن.
۳. دکمه **Run workflow** → برنچ `arena/019fa8cd-fbtcryp` را انتخاب کن →
   **Run workflow**.
۴. حدود ۳ دقیقه صبر کن. صفحه را رفرش کن تا تیک سبز بیاید.

**قبل از هر کاری، لاگ را چک کن که واقعاً امضا شده.** روی run کلیک کن → روی
مرحله `bash ci/build-apk.sh` → دنبال این خط بگرد:

```
▸ building SIGNED release APK
```

اگر به‌جایش این را دیدی:

```
▸ no keystore supplied — building debug APK
```

یعنی مرحله ۱ یا ۲ ناقص مانده. برگرد و دوباره چک کن. **با نسخه debug جلوتر
نرو** — گوگل قبولش نمی‌کند و فقط وقتت تلف می‌شود.

## مرحله ۵ — فایل را بردار

بعد از بیلد موفق، دو فایل ساخته می‌شود:

| فایل | برای چه |
|---|---|
| **`app-release.aab`** | **همین را به گوگل‌پلی می‌دهی** |
| `app-release.apk` | برای نصب مستقیم روی گوشی خودت، و برای کافه‌بازار و مایکت |

### لینک دانلود

صفحه انتشار (بعد از بیلد موفق، فایل‌ها اینجا ظاهر می‌شوند):

**<https://github.com/mshiravi433-ctrl/fbtcryp/releases/tag/latest>**

لینک مستقیم فایل‌ها بعد از بیلد امضاشده:

- برای گوگل‌پلی →
  `https://github.com/mshiravi433-ctrl/fbtcryp/releases/download/latest/app-release.aab`
- برای نصب روی گوشی →
  `https://github.com/mshiravi433-ctrl/fbtcryp/releases/download/latest/app-release.apk`

> **الان روی آن صفحه فقط `app-debug.apk` هست** (۶٫۸ مگابایت، بیلد ۲۸ جولای).
> این نسخه روی گوشی نصب می‌شود و برای تست خوب است، ولی به درد گوگل‌پلی
> نمی‌خورد چون با کلید عمومی دیباگ اندروید امضا شده، نه کلید تو.
> فایل‌های `app-release.*` تازه بعد از انجام مرحله‌های ۱ تا ۴ ساخته می‌شوند.

یک چیز را هم درست کردم: قبلاً حتی وقتی بیلد امضاشده بود، فایل با اسم
`app-debug.apk` هم منتشر می‌شد. یعنی از روی اسم نمی‌فهمیدی امضا شده یا نه —
و این تنها چیزی است که قبل از آپلود باید بدانی. حالا اسم فایل همیشه نوع
واقعی بیلد را نشان می‌دهد.

## مرحله ۶ — آپلود در Play Console

۱. <https://play.google.com/console> → ثبت‌نام (۲۵ دلار، یک‌بار برای همیشه).
۲. **Create app** → نام `FBT Swap`، زبان پیش‌فرض **English (United States)**،
   نوع **App**، **Free**.
۳. از منوی چپ: **Testing** → **Internal testing** → **Create new release**.
۴. فایل `app-release.aab` را آپلود کن.
۵. **App integrity** → بخش Play App Signing را تأیید کن.
۶. متن‌های معرفی را از `store/LISTING-FA.md` و `store/LISTING-EN.md` کپی کن،
   آیکون و feature graphic را از پوشه `store/` آپلود کن.
۷. اسکرین‌شات‌ها را با گوشی خودت بگیر (ترتیب دقیق در فایل `LISTING-FA.md`).
۸. فرم‌های **Data safety**، **Content rating** و **App content** را با
   جواب‌های همان فایل پر کن.
۹. **Send for review**.

**چرا Internal testing و نه Production:** در چند دقیقه منتشر می‌شود نه چند
روز، با یک لینک روی گوشی خودت نصب می‌شود، و اگر `VITE_API_BASE` را اشتباه
زده باشی خودت می‌فهمی نه بازبین گوگل. هر رد شدن در بازبینی در پرونده حساب
توسعه‌دهنده‌ات ثبت می‌ماند.

وقتی روی گوشی خودت باز شد و یک سواپ آزمایشی درست انجام شد، همان نسخه را با
دکمه **Promote release** به Production ببر.

## وقتی خطا دیدی

| در لاگ می‌بینی | یعنی | کار |
|---|---|---|
| `no keystore supplied` | secret به اسکریپت نرسیده | مرحله ۱ (بلوک `env:`) و مرحله ۲ |
| `Invalid keystore format` | رشته base64 چندخطی شده | دوباره کپی کن، در یک خط |
| `Keystore was tampered with, or password was incorrect` | رمز غلط | `ANDROID_KEYSTORE_PASSWORD` را چک کن |
| `Failed to read key fbt from store` | نام alias غلط | `ANDROID_KEY_ALIAS` باید `fbt` باشد |
| بیلد سبز شد ولی `.aab` نیست | workflow قدیمی است | مرحله ۱ را انجام نداده‌ای |
| Play می‌گوید `Version code 1 has already been used` | نسخه تکراری | `APP_VERSION_CODE` را یکی زیاد کن و دوباره بیلد بگیر |

## و یک هشدار که هر دفعه تکرار می‌کنم

فایل keystore و رمزهایش را در **دو جای جدا** نگه دار — مثلاً یک نسخه در
حافظه گوشی و یک نسخه رمزگذاری‌شده در فضای ابری. نه هر دو روی همان گوشی.

اگر این فایل را گم کنی، **نمی‌توانی اپ خودت را آپدیت کنی**. گوگل لیست اپ را
برای همیشه به این کلید گره می‌زند. راه‌حلی وجود ندارد؛ باید اپ جدید با نام
پکیج جدید بسازی و همه نصب‌های قبلی یتیم می‌شوند. این دقیقاً مثل عبارت بازیابی
کیف پول است.
