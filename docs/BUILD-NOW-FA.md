## گام ۱ — Groq را وصل کن (۲ دقیقه، هوش مصنوعی درست می‌شود)

Groq را به‌عنوان **ارائه‌دهنده اول** اضافه کردم. دلیلش مهم است: Gemini در
چند کشور از جمله ایران مسدود است و خطایی می‌دهد که شبیه باگ اپ به نظر می‌رسد.
Groq این محدودیت را ندارد و سهمیه رایگان واقعی دارد.

در Vercel → پروژه‌ات → Settings → Environment Variables:

| Name | Value |
|---|---|
| `GROQ_API_KEY` | کلید **جدیدی** که ساختی |
| `GROQ_MODEL` | `openai/gpt-oss-20b` |

⚠️ **پیشوند `VITE_` نگذار.** هر متغیری با آن پیشوند داخل فایل جاوااسکریپت
کامپایل می‌شود و همه کاربران می‌توانند کلیدت را بخوانند.

بعد از Redeploy، این آدرس را باز کن:

```
https://<اپ-تو>.vercel.app/api/ai/diagnose
```

اگر `"ok": true` دید، هوش مصنوعی کار می‌کند. اگر نه، دقیقاً می‌گوید چه چیزی
خراب است و چطور درستش کنی.

## گام ۲ — کلید امضا بساز (فقط یک بار، ۵ دقیقه)

**این تنها کاری است که واقعاً فقط خودت می‌توانی انجام دهی.** اگر من کلید را
بسازم، من کلید اپ تو را دارم — این مثل دادن عبارت بازیابی کیف پول است.

Termux را از **F-Droid** نصب کن (نسخه Play Store قدیمی و خراب است):

```bash
pkg update -y && pkg install openjdk-17 -y
```

بعد این را اجرا کن. مقادیر تو از قبل داخلش هست:

```bash
mkdir -p ~/fbt && cd ~/fbt

keytool -genkeypair -v \
  -keystore fbt-release.keystore \
  -alias fbt \
  -keyalg RSA -keysize 2048 -validity 10950 \
  -dname "CN=FBT Company, OU=Mobile, O=Fanous Bazaar Pishgam, L=Isfahan, ST=Isfahan, C=IR"
```

دو بار رمز می‌پرسد. **یک رمز قوی بساز و روی کاغذ بنویس.** (رمزی که در چت
فرستادی را استفاده نکن.)

حالا خروجی base64 را بگیر:

```bash
base64 -w 0 fbt-release.keystore > ks.txt
cat ks.txt
```

آن رشته بلند را کپی کن.

> **⚠️ مهم‌ترین جمله این سند:** فایل `fbt-release.keystore` را در **دو جای
> جدا** پشتیبان بگیر. گوگل لیست اپ تو را برای همیشه به این کلید گره می‌زند.
> اگر گمش کنی، نمی‌توانی اپ خودت را آپدیت کنی — باید لیست جدید با نام پکیج
> جدید بسازی و همه نصب‌های قبلی یتیم می‌شوند.

## گام ۳ — GitHub

`Settings → Secrets and variables → Actions`

**Secrets** (تب Secrets):

| Name | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | محتوای `ks.txt` |
| `ANDROID_KEYSTORE_PASSWORD` | رمزی که ساختی |
| `ANDROID_KEY_ALIAS` | `fbt` |
| `ANDROID_KEY_PASSWORD` | همان رمز |

**Variables** (تب Variables — اینها عمومی‌اند):

| Name | Value |
|---|---|
| `VITE_API_BASE` | `https://<اپ-تو>.vercel.app/api` |
| `VITE_DISABLE_GAMES` | `true` |
| `APP_VERSION_CODE` | `1` |
| `APP_VERSION_NAME` | `1.0.0` |

**`VITE_DISABLE_GAMES=true` را جدی بگیر.** حتی با امتیاز بی‌ارزش، بخش‌های
Crash و Dice و Mines برای بازبین گوگل قمار به نظر می‌رسند و شایع‌ترین دلیل رد
شدن اپ‌های کریپتو است. تست کردم که این تنظیم کد را کاملاً از باندل حذف می‌کند،
نه فقط مخفی.

**برای هر انتشار بعدی، `APP_VERSION_CODE` را یکی زیاد کن.** گوگل آپلودی که
شماره‌اش بالاتر نباشد را رد می‌کند.

## آنچه در این نوبت درست شد

| مورد | وضعیت |
|---|---|
| هوش مصنوعی راهنما | Groq اضافه شد (بدون مسدودیت جغرافیایی) + تشخیص خودکار علت خطا |
| تکان خوردن منو | دو علت واقعی پیدا و رفع شد |
| باگ‌های سواپ | سه باگ در دکمه MAX + مقایسه موجودی |
| تم روشن | پیش‌فرض شد + رفع نوارهای سیاه در صفحات تمام‌صفحه |
| شماره تلفن | به صفحه تماس اضافه شد (Play لازم دارد) |

### تکان خوردن منو — دو علت داشت

۱. هایلایت تب فعال و دکمه «بیشتر» هر دو `layoutId="nav-glow"` داشتند. موقع
باز شدن منو هر دو یک لحظه هم‌زمان وجود داشتند، پس Framer Motion سعی می‌کرد یک
عنصر مشترک را به دو جا ببرد.

۲. باز شدن منو `overflow:hidden` می‌گذاشت که نوار اسکرول را حذف می‌کند و
حدود ۱۵ پیکسل عرض آزاد می‌شود — کل صفحه از جمله نوار پایین جابه‌جا می‌شد.

### باگ‌های سواپ — هر سه به تراکنش برگشت‌خورده ختم می‌شدند

دکمه MAX از `toFixed(8)` استفاده می‌کرد که **گرد می‌کند**. روی موجودی بزرگ
**رو به بالا** گرد می‌کرد، یعنی مبلغی بیشتر از موجودی واقعی — تراکنش برمی‌گشت
و کاربر گس را از دست می‌داد. همچنین موجودی‌های کوچک توکن‌های ۱۸ رقمی را صفر
می‌کرد. و ذخیره گس ثابت `0.002` بود که روی BNB حدود ۱ دلار ولی روی اتریوم
حدود ۷ دلار است.
