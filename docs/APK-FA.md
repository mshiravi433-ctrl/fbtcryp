## ✅ APK آماده است

build با موفقیت انجام شد. دو راه برای دانلود:

### راه ۱ — از صفحه Release (ساده‌تر)

```
github.com/mshiravi433-ctrl/fbtcryp/releases
```

### راه ۲ — از Actions

```
github.com/mshiravi433-ctrl/fbtcryp/actions/runs/30300111212
```

صفحه را باز کن → پایین بیا → بخش **Artifacts** → روی **FBT-Swap-apk** بزن.

> برای دانلود از Artifacts باید در گیت‌هاب **لاگین** باشی. اگر لاگین نیستی
> دکمه دانلود کار نمی‌کند. Release این محدودیت را ندارد.

### نصب روی گوشی

۱. فایل `.zip` دانلود می‌شود → با فایل‌منیجر بازش کن → `app-debug.apk` را بگیر
۲. روی فایل apk بزن
۳. اندروید هشدار «نصب از منابع ناشناس» می‌دهد — این برای هر APK خارج از
   گوگل‌پلی عادی است
۴. **Settings** → اجازه بده → **Install**
۵. بعد از نصب، آن اجازه را دوباره خاموش کن

**مشخصات build:**

| مورد | مقدار |
|---|---|
| حجم | ۴.۵۴ مگابایت |
| نام بسته | `ir.fbt.swap` |
| نام اپ | FBT Swap |
| امضا | debug (برای تست و توزیع مستقیم) |
| کارمزد | ۰.۵٪ → `0xaf5CE154cEfd22Da5BD1D0a54479E81963A224d6` |

> ⚠️ نسخه **debug-signed** است. برای انتشار در Google Play باید release build
> با کلید امضای خودت بسازی.

## به‌روزرسانی پیشنهادی workflow

نسخه فعلی فقط artifact می‌سازد که برای دانلود نیاز به لاگین دارد. اگر
`ci/build-apk-minimal.yml` را دوباره در
`.github/workflows/build-apk.yml` کپی کنی، از این به بعد APK **خودکار** در
صفحه Releases هم منتشر می‌شود و بدون لاگین با یک لمس نصب می‌شود.

---

## تاریخچه مشکل (حل شد)

### مشکل چه بود

فایل `.github/workflows/build-apk.yml` روی گیت‌هاب **۱۷ بایت** است و محتوایش
فقط این یک خط است:

```
ci/build-apk.yml
```

یعنی به‌جای **محتوای** فایل، **اسم** فایل paste شده. گیت‌هاب این را به‌عنوان
دستورالعمل build نمی‌شناسد، برای همین هر سه اجرا بلافاصله fail شده‌اند
(زمان اجرا: `0s` — یعنی حتی شروع هم نشده).

این خطای رایجی است: در گیت‌هاب موبایل، وقتی روی اسم فایل می‌زنی گاهی
به‌جای باز کردنش، اسمش را کپی می‌کند.

---

## راه‌حل: نسخه کوتاه

فایل اصلی ۱۰۵ خط بود که روی موبایل کپی کردنش سخت است. یک نسخه **۲۶ خطی**
ساختم که همان کار را می‌کند.

### روش A — تایپ مستقیم (مطمئن‌ترین، ۳ دقیقه)

چون کپی روی موبایل مشکل‌ساز شده، می‌توانی مستقیم تایپش کنی. فقط ۲۶ خط است.

**۱.** برو به این آدرس (مستقیم صفحه ویرایش را باز می‌کند):

```
github.com/mshiravi433-ctrl/fbtcryp/edit/arena/019fa427-fbtcryp/.github/workflows/build-apk.yml
```

**۲.** هر چه داخل کادر هست را **کامل پاک کن**

**۳.** این را دقیقاً تایپ یا paste کن:

```yaml
name: Build APK
on: [push, workflow_dispatch]
permissions:
  contents: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: 17
      - uses: android-actions/setup-android@v3
      - run: npm ci
      - run: npm run build
      - run: npx cap sync android
      - run: chmod +x android/gradlew
      - run: cd android && ./gradlew assembleDebug --no-daemon
      - uses: actions/upload-artifact@v4
        with:
          name: FBT-Swap-apk
          path: android/app/build/outputs/apk/debug/app-debug.apk
```

> ⚠️ **فاصله‌ها (space) در YAML حیاتی‌اند.** از Tab استفاده نکن — فقط Space.
> اگر تایپ می‌کنی، دقیقاً همان تعداد فاصله ابتدای هر خط را رعایت کن.

**۴.** پایین صفحه → **Commit changes** → **Commit directly** → تایید

---

### روش B — کپی درست از فایل

اگر می‌خواهی کپی کنی، این‌طور مطمئن باش که محتوا کپی می‌شود نه اسم:

**۱.** این لینک را باز کن (نسخه raw، فقط متن خالی است):

```
raw.githubusercontent.com/mshiravi433-ctrl/fbtcryp/arena/019fa427-fbtcryp/ci/build-apk-minimal.yml
```

**۲.** صفحه‌ای می‌بینی که فقط متن دارد. یک جای متن **نگه دار** →
**Select all** → **Copy**

**۳.** حالا صفحه ویرایش را باز کن:

```
github.com/mshiravi433-ctrl/fbtcryp/edit/arena/019fa427-fbtcryp/.github/workflows/build-apk.yml
```

**۴.** محتوای قبلی را پاک کن → paste کن → **Commit changes**

> 💡 تفاوت مهم: صفحه `raw.githubusercontent.com` فقط متن خالی است، پس
> Select all دقیقاً محتوا را می‌گیرد. صفحه معمولی گیت‌هاب دکمه‌ها و منو هم
> دارد که کپی را خراب می‌کند.

## چطور بفهمم درست شد

بعد از commit:

**۱.** به تب **Actions** برو

**۲.** یک اجرای جدید با نام **Build APK** می‌بینی که در حال اجراست
(دایره زرد چرخان 🟡)

**۳.** علائم موفقیت در همان نگاه اول:

| نشانه | یعنی |
|---|---|
| نام اجرا **Build APK** است | ✅ فایل درست خوانده شد |
| زمان اجرا بیشتر از چند ثانیه است | ✅ واقعاً شروع شده |
| نام اجرا `.github/workflows/build-apk.yml` است | ❌ هنوز خرابه |
| زمان `0s` و فوراً قرمز | ❌ هنوز خرابه |

**۴.** حدود **۵ تا ۸ دقیقه** صبر کن تا تیک سبز ✅ شود

**۵.** روی اجرا بزن → پایین صفحه بخش **Artifacts** →
**FBT-Swap-apk** را دانلود کن

**۶.** یک فایل `.zip` دانلود می‌شود. با فایل‌منیجر گوشی بازش کن و
فایل `.apk` داخلش را نصب کن

## اگر باز هم fail شد

این بار احتمالاً واقعاً build شروع شده ولی وسط کار خطا خورده — که خبر خوبی
است، یعنی فایل درست است.

برای دیدن خطا:

1. روی اجرای قرمز بزن
2. روی **build** بزن
3. مرحله‌ای که کنارش ❌ قرمز است را باز کن
4. آخرین ۱۰-۲۰ خط را برای من بفرست

خطاهای محتملی که ممکن است ببینی:

| خطا | معنی | راه‌حل |
|---|---|---|
| `npm ci` fail | ناهماهنگی lockfile | برایم بفرست، درست می‌کنم |
| `SDK license not accepted` | مجوز اندروید | برایم بفرست |
| `Unsupported class file major version` | نسخه جاوا | یعنی `java-version` عوض شده، باید ۱۷ باشد |
| `out of memory` | حافظه runner | برایم بفرست، تنظیمش می‌کنم |

---

## خلاصه

سه اجرای قبلی fail شدند چون فایل workflow به‌جای محتوا، **اسم فایل** را
داشت. فایل را با محتوای درست (۲۶ خط بالا) جایگزین کن و build خودش شروع
می‌شود.

من نمی‌توانم این فایل را برایت درست کنم — گیت‌هاب به اپ‌ها اجازه نوشتن در
پوشه `.github/workflows/` را نمی‌دهد (حتی ویرایش فایل موجود). این تنها
قسمتی از کل پروژه است که حتماً باید خودت انجامش بدهی.
