# vercel.json — چرا داخلش کامنت ننویسیم

> این فایل را نوشتم چون یک اشتباه من باعث شد **۷ دیپلوی پشت سر هم شکست بخورد** و هیچ‌کدام از کارهای دو ساعت گذشته روی سایت نرود.

---

## چه اتفاقی افتاد

وقتی هدرهای کش را اضافه کردم (برای حل کندی سایت)، عادت همیشگی‌ام را ادامه دادم: کنار هر تنظیم توضیح نوشتم که چرا آن‌طور است.

چون JSON کامنت ندارد، از ترفند رایج `"//"` استفاده کردم:

```json
{
  "//": "BUILD ARTEFACTS — cached for a year, and it is safe...",
  "source": "/assets/(.*)",
  "headers": [ ... ]
}
```

این ترفند در `package.json` و خیلی جاهای دیگر کار می‌کند. **در `vercel.json` کار نمی‌کند.**

## چرا

اسکیمای رسمی ورسل — همان `https://openapi.vercel.sh/vercel.json` که در خطِ اول فایل نوشته شده — این را دارد:

```json
"additionalProperties": false
```

یعنی **هر کلیدی که در فهرست رسمی نباشد، فایل را نامعتبر می‌کند**. `"//"` هم دقیقاً همین است.

نتیجه: ورسل فایل را رد کرد و بیلد قبل از شروع شکست خورد.

## چرا دیر فهمیدمش

این بدترین بخش ماجراست و ارزش نوشتن دارد:

- ✅ بیلد لوکال درست کار می‌کرد (`npx vite build`)
- ✅ همه ۱۹۱۴ تست پاس می‌شد
- ✅ `git push` موفق بود
- ✅ `main` هم به‌روز می‌شد
- ❌ ولی سایت عوض نمی‌شد

من مدام فایل جدید را روی سایت چک می‌کردم و ۴۰۴ می‌گرفتم، و **فرض کردم CDN کند است**. حدود بیست دقیقه صبر کردم و حتی یک راه دور زدن ساختم (کلید را از API سرو کردم) — که آن هم دیپلوی نشد، چون علت اصلی همان بود.

اشتباه من این بود که به‌جای **دیدن وضعیت دیپلوی**، درباره‌اش **حدس زدم**.

## چطور پیدا شد

```bash
gh api repos/mshiravi433-ctrl/fbtcryp/deployments --jq '.[0].id'
gh api repos/mshiravi433-ctrl/fbtcryp/deployments/<id>/statuses --jq '.[0].state'
```

جواب: `failure` — و وقتی عقب‌تر رفتم، هفت‌تای پشت سر هم. آخرین موفق `e7bd757` بود، و اولین شکست دقیقاً همان کامیتی که `vercel.json` را دست زده بودم.

## 📌 قانون از این به بعد

### ۱. در `vercel.json` هیچ کامنتی ننویس

اگر توضیحی لازم است، در همین فایل (`docs/VERCEL-JSON-RULES.md`) بنویس یا در `server/app.js` کنار همان منطق — که آنجا جاوااسکریپت است و کامنت می‌پذیرد.

### ۲. بعد از هر پوش، وضعیت دیپلوی را چک کن

```bash
gh api repos/mshiravi433-ctrl/fbtcryp/deployments \
  --jq '[.[] | select(.environment | startswith("Production"))][0].id' \
| xargs -I{} gh api repos/mshiravi433-ctrl/fbtcryp/deployments/{}/statuses \
  --jq '.[0].state'
```

`success` یعنی رفت. `failure` یعنی هرچه بعدش می‌بینی از نسخه قدیمی است.

### ۳. «سایت عوض نشده» را هیچ‌وقت به کندی CDN نسبت نده

اول دیپلوی را چک کن. تفاوتش بین بیست دقیقه انتظار بی‌هوده و یک اصلاح دو دقیقه‌ای است.

## چیز دیگری که یاد گرفتم

دو لایه محافظ داشتم و **هیچ‌کدام این را نگرفت**:

| لایه | چرا نگرفت |
|---|---|
| ۱۹۱۴ تست | هیچ‌کدام `vercel.json` را با اسکیمای ورسل اعتبارسنجی نمی‌کرد |
| بیلد لوکال | `vite build` اصلاً `vercel.json` را نمی‌خواند |

برای همین یک تست جدید اضافه کردم که `vercel.json` را می‌خواند و اگر کلید ناشناخته‌ای (از جمله `"//"`) داشته باشد رد می‌شود. با خرابکاری عمدی هم تستش کردم.

اگر ابزارِ خودت نمی‌تواند خطایی را ببیند، آن خطا دوباره اتفاق می‌افتد.
