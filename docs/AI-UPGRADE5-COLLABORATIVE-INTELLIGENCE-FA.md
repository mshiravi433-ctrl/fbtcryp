# AI Upgrade 5 — هوش مشارکتی چندمدله + تحقیق وب + هوش سؤالات مشتریان

> روی Upgrade 1–4 ساخته شده؛ همه زیرساخت موجود (AI Gateway، Intent OS، Consensus،
> Confidence، Learning Loop) بدون تغییر باقی مانده و فقط یک لایه هوشمندی جدید روی آن
> نشسته است. سازگاری عقب‌گرد کامل: اگر هیچ کلید AI پیکربندی نشده باشد یا همه
> ارائه‌دهنده‌ها از کار بیفتند، پاسخ‌های قطعی (deterministic) قبلی سر جای خود می‌مانند.

---

## ۱) هدف

کاربر یک بار با FBT حرف می‌زند؛ پشت صحنه چند مدل تخصصی، داده زنده، تحقیق وب و
ابزارهای داخلی با هم همکاری می‌کنند تا **یک پاسخ واحد و قابل اتکای FBT** تولید شود.

```
کاربر → Intent OS → تحلیل سؤال → موتور همکاری → مدل‌ها (موازی)
      → تحقیق وب → داده ابزار → راستی‌آزمایی → اجماع → پاسخ نهایی FBT → کاربر
```

کاربر هرگز «Grok گفت… / Claude گفت…» نمی‌بیند؛ فقط در حالت شفافیت (transparency)
دیدگاه هر نقش قابل مشاهده است.

## ۲) اجزای جدید

| فایل | نقش |
|---|---|

| `src/lib/intent-ai/os/questionIntel.js` | هسته هوش سؤالات مشتری: خوشه‌بندی، شکاف دانش، نامزد FAQ، طبقه‌بندی بازخورد |

## ۳) سطح‌های همکاری (کنترل هزینه)

| سطح | چه چیزی | مثال |
|---|---|---|
| ۱ | یک مدل سریع | «سلام»، «ممنون»، «BTC چیه؟» هیچ‌وقت بالاتر نمی‌روند |
| ۲ | یک مدل + ابزار/دانش | سؤال دانشی/محصولی |
| ۳ | دو مدل + ابزار (+وب اگر زنده) | «چرا بیت کوین امروز افت کرد؟» |
| ۴ | چندمدل + وب + راستی‌آزمایی | «آیا این خبر می‌تواند باعث ریزش BTC شود؟» |
| ۵ | همکاری کامل + راستی‌آزمایی + عدم‌قطعیت | «الان همه پولم رو بیت کوین بخرم؟» |

## ۴) قوانین کلیدی

1. **اجماع AI ≠ حقیقت.** ادعای factual فقط وقتی «verified» است که داده ابزار یا
   شاهد وب (tier ≤ ۳) پشتیبانی کند؛ در غیر این صورت `aiConsensusOnly` علامت می‌خورد.
2. **هرگز داده زنده جعل نمی‌شود.** قیمت/موجودی/تراکنش فقط از ابزار؛ اگر منبع نیست:
   «این داده را در حال حاضر نمی‌توانم به‌طور معتبر تأیید کنم.»
3. **اختلاف مدل‌ها پنهان نمی‌شود.** اجماع اجباری نداریم؛ `disagreement: true` ثبت و
   در پاسخ منعکس می‌شود.
4. **احساسات:** ترس/پانیک → همدلی + ریسک + بررسی ساختاریافته، بدون اطمینان‌بخشی کاذب.
   FOMO → فرصت + ریسک + جایگزین + عدم‌قطعیت، بدون تقویت هیجان.
5. **امنیت اجرا دست‌نخورده (§۶۷):** همکاری چندمدله هیچ اختیار اجرایی جدیدی نمی‌سازد.
   امضا، تأیید و مسیر execution دقیقاً همان قبلی است.
6. **حریم خصوصی (§۲۸/§۴۴):** کلید خصوصی/عبارت بازیابی/سکرت هرگز ذخیره یا ارسال
   نمی‌شود؛ پرتفوی فقط به‌صورت خلاصه تجمیعی به مدل می‌رود.
7. **FAQ نامزد = پیش‌نویس.** از خوشه‌های واقعی سؤال تولید می‌شود ولی تا بازبینی انسانی
   `reviewed: false` و `publishable: false` می‌ماند.

## ۵) تازگی (Freshness)

`STATIC` (دانش پایدار — بدون وب) → `RECENT` (وب کمک می‌کند) → `LIVE` (وب لازم است) →
`BREAKING` (وب + تأیید چندمنبعی). شبکه‌های اجتماعی Tier 4 = «سرنخ»، نه واقعیت تأییدشده.

## ۶) APIهای جدید (زیر `/api/v1/ai`)

| مسیر | توضیح | دسترسی |
|---|---|---|
| `POST /collaborate` | تحلیل مشارکتی صریح | عمومی |
| `POST /research` | تحقیق وب با منابع رتبه‌بندی‌شده | عمومی |
| `POST /news-impact` | موتور تأثیر خبر بر کریپتو (امتیاز تحلیلی، نه تضمین) | عمومی |
| `POST /feedback` | 👍/👎 با دلیل (تغذیه ارزیابی، نه خودیادگیری کنترل‌نشده) | عمومی |
| `GET /knowledge` + `POST /knowledge/search` | مرکز دانش | عمومی |
| `GET /questions/analytics` | سؤالات برتر/نوظهور/بی‌پاسخ/پرحساسیت | فقط `CRON_SECRET` |
| `GET /questions/gaps` | شکاف‌های دانش + پیشنهاد | فقط `CRON_SECRET` |
| `GET /questions/faq-candidates` | نامزدهای FAQ (پیش‌نویس) | فقط `CRON_SECRET` |
| `GET /quality` | داشبورد کیفیت AI + سلامت ارائه‌دهنده‌ها | فقط `CRON_SECRET` |

پاسخ چت علاوه بر فیلدهای قبلی، `reply.intelligence` را حمل می‌کند: سطح، تازگی،
احساس، منابع، عدم‌قطعیت، امتیاز کیفیت. UI فقط منابع (https)، هشدار عدم‌قطعیت بالا و
دکمه‌های بازخورد را نشان می‌دهد — پیچیدگی داخلی به کاربر نمایش داده نمی‌شود.

## ۷) متغیرهای محیطی جدید

```
AI_COLLAB_DEADLINE_MS=20000   # سقف زمانی کل همکاری در یک نوبت چت
AI_COLLAB_MAX_MODELS=4        # حداکثر مدل در هر سؤال
```

هیچ کلید جدیدی لازم نیست؛ ارائه‌دهنده‌ها از همان کلیدهای موجود
(GROK/OPENROUTER/GROQ/GEMINI/OPENAI/ANTHROPIC/…) به‌صورت پویا کشف می‌شوند و
تحقیق وب از `JINA_API_KEY` (در صورت وجود) و در غیر این صورت DuckDuckGo استفاده می‌کند.
