# ۲۰۲۶-۱۰-۲۶ — تاریخچهٔ فیوچرز در وب، راستی‌آزمایی محدود TP/SL و هم‌راستاسازی کاتالوگ آن‌چین

## خلاصهٔ تصمیم

این پیگیری فقط rollout وبِ تاریخچه را فعال می‌کند. TP/SL دی‌وای‌دی‌ایکس تا دریافت
شواهد زندهٔ testnet خاموش می‌ماند. دسته‌بندی تب On-Chain مطابق کدِ ارسال‌شده
کریپتو-محور نگه داشته می‌شود؛ بازارهای سنتی همچنان فقط با لینک به صفحهٔ
`/stocks?tab=ostium` می‌روند.

## ۱. تاریخچهٔ فقط‌خواندنی

`FuturesHistory.jsx` و `futuresHistory.js` قبل از فعال‌سازی از نظر مسیر و قرارداد
داده بازبینی شدند:

- کنترل‌ها فقط خواندن، فیلتر و صفحه‌بندی می‌کنند؛ هیچ ارسال، لغو یا ویرایشی ندارند.
- dYdX فیل‌ها و سفارش‌های پرشده را از مسیرهای GET پروکسی هم‌مبدأ می‌گیرد؛ جهت و
  وضعیت باز/بسته فقط از سفارش جفت‌شده استخراج می‌شود و اگر سفارش پیدا نشود جهت
  «نامشخص» باقی می‌ماند.
- فیل‌های dYdX سود محقق‌شده ندارند؛ ستون PnL عمداً «—» است و نه صفر و نه مقدار
  محاسبه‌شده.
- Ostium و Velocity هر دو با دلیل صریح «در دسترس نیست» می‌مانند؛ برایشان فیل،
  قیمت، کندل، سود یا تاریخچه ساخته یا حدس زده نمی‌شود.
- تب اکنون در ریل `/perp` فقط وقتی ظاهر می‌شود که `SPECULATION_ENABLED` و
  `FUTURES_HISTORY_ENABLED` هر دو فعال باشند. پیوند «رفتن به dYdX» نیز به همان
  تب موجود می‌رود.

فلگ در `src/lib/features.js` همچنان به‌صورت پیش‌فرض خاموش است. مسیر واقعی وب
`npm run build:full` فایل `ci/web-season.env.sh` را پیش از Vite بارگذاری می‌کند؛
این فایل فقط در `VERCEL_ENV=production` مقدار
`VITE_ENABLE_FUTURES_HISTORY=true` می‌گذارد و preview/development را خاموش نگه
می‌دارد. `android:sync` همچنان هر سه فلگ تازه را صریحاً `false` می‌کند و این
پیگیری آن را تغییر نمی‌دهد. آزمونِ مستقلِ Vite و خروجی build نهایی باید حضور
فلگ و چانک/مسیر تب را ثابت کنند.

## ۲. TP/SL دی‌وای‌دی‌ایکس — testnet هنوز تأیید نشده

SDK در `package.json` و lockfile همان `@dydxprotocol/v4-client-js@3.4.0` است؛
`DYDX_TPSL_ENABLED` خاموش می‌ماند.

در محیط این اجرا probe زندهٔ testnet انجام نشد: egress این محیط به میزبان‌های
محدود allowlist شده است و endpointهای dYdX testnet در آن فهرست نیستند؛ هیچ
اعتبارنامهٔ testnet از محیط در دسترس نبود. بنابراین نه زمان انقضای لغو سفارش
شرطی و نه رفتار سفارش LIMIT+IOC با SDK واقعی و testnet تأیید نشده‌اند. تست‌های
محلی/ساختگی جای این شواهد را نمی‌گیرند. هیچ کلید، seed یا mnemonic ساخته،
دریافت، چاپ یا ذخیره نشد؛ هیچ درخواست امضاشده، تراکنش testnet یا mainnet ارسال
نشد.

**گام دستی باقی‌مانده پیش از فعال‌سازی:** از محیطی با دسترسی مجاز به dYdX
testnet، با یک حساب/کیف testnet تازه و فقط محلی، روی SDK پین‌شدهٔ 3.4.0:
(۱) یک سفارش شرطی reduce-only بسازید، زمان انقضا/لغو را تا عبور از مهلت مشاهده
و سپس وضعیت/لغو را از indexer بررسی کنید؛ (۲) یک سفارش شرطی LIMIT با IOC را
trigger کنید و وضعیت سفارش، مقدار پرشده/باقی‌مانده و لغو بخش باقی‌مانده را در
indexer تأیید کنید. کلید فقط در فایل محلی خارج از ریپو باشد و در log، گزارش، CI
یا commit قرار نگیرد. تا ثبت هر دو نتیجهٔ قابل بازبینی، فلگ باید خاموش بماند.

برچسب «برآورد» سود/زیان و نشست dYdX فقط‌درحافظه دست‌نخورده می‌مانند.

## ۳. اصلاح کاتالوگ و چنج‌لاگ

ادعای قدیمیِ ورودی `Unreleased — On-Chain futures: Drift → Velocity migration`
که از ادغام کاتالوگ همهٔ ونیوها و چیپ‌های Forex/کالا/شاخص/سهام/ETF می‌گفت، با
کد ارسالی سازگار نیست. در `FuturesOnchain.jsx`، `ONCHAIN_VENUES` فقط
`['drift']` است، `CATEGORY_ORDER` فقط `Crypto` را دارد و کامنت بالای فایل تصمیم
محصولی فعلی را صریح می‌کند: تب فقط کریپتو است و بازارهای سنتی با دکمهٔ موجود به
`/stocks?tab=ostium` می‌روند. شناسهٔ `drift` نام داخلیِ سازگار با ledger برای
مسیر اجرایی Velocity است؛ وجود آداپتر/رجیستری چندپروتکلی به‌تنهایی مجوز
ادغام UI نیست. بنابراین ادعای تاریخی به‌عنوان **ناسازگار با کد ارسال‌شده** در
این ورودی تازهٔ چنج‌لاگ اصلاح شده است؛ تصمیم محصول برای گسترش چندونوویی تغییر
نکرده است.

نگاشت‌های Forex، کالا، شاخص، سهام و ETF از `friendlyCategory` حذف شدند، چون با
`CATEGORY_ORDER` فعلی هرگز چیپ قابل‌دسترسی نمی‌ساختند. نگاشت Crypto و fallback
`Other` حفظ شده‌اند؛ testidها، رندر چیپ‌ها، لینک بازارهای سنتی و کلیدهای locale
تغییر نکرده‌اند.

## ۴. عمداً خارج از محدوده

- روشن‌کردن `VITE_ENABLE_DYDX_TPSL` بدون شواهد کامل testnet.
- فعال‌سازی ریفرر Velocity (ساخت حساب با keypair محلی، ست‌کردن envها و cron
  sweep)، چون عملیات اپراتوریِ هزینه‌دار حدود ۱–۲ دلار است.
- هر تراکنش mainnet، هزینه، کلید خصوصی/seed/mnemonic در repo یا گزارش، یا ساخت
  دادهٔ بازار/تاریخچه/PnL.
- تغییر منطق کارمزد سه مسیر، تولید باندل vendor در `build:full`،
  `SPECULATION_ENABLED` و رفتار صریح خاموش Android.

## ۵. راستی‌آزمایی

- `npm run test:tpsl-depth-history`: سبز — سوئیت Node/activation **۶۴/۶۴**، پروکسی HTTP **۱۴/۱۴**، Vitest UI **۱۶/۱۶**.
- `npm run test:futures`: سبز — موتور + BFF **۵۰/۵۰** و باندل SDK Velocity **۳۷/۳۷**. پیش از آن `npm run vendor:velocity` برای تولید باندل vendor محلیِ gitignored اجرا شد؛ این پیش‌نیاز probe بود و به تولید vendor در `build:full` تغییری نداد.
- `npm run test:futures-onchain`: سبز **۶۲/۶۲**. `npm test` نیز همین probe را ابتدا از طریق script صریح اجرا می‌کند و **۶۲/۶۲** می‌گیرد؛ سپس runner قدیمی به‌دلیل `process.exit` در probeٔ Business پس از `Business locale probe: PASS` متوقف می‌شود (رفتار موجود؛ ادعای اجرای همهٔ suiteهای پشت آن نیست).
- `test/wiring.mjs`: روی بیس‌لاین دقیق `main` **۶۰ شکست از ۲۹۶۶**؛ در این شاخه **۵۹ از ۲۹۶۶** و همهٔ نام‌های باقی‌مانده عیناً همان بیس‌لاین‌اند. تنها بررسی قدیمی «دقیقاً سه تب» با شرط history-web عوض شد؛ هیچ شکست تازه‌ای باقی نماند.
- `npm run build`: سبز. با `VERCEL_ENV=production`، source کردن `ci/web-season.env.sh` و همان `VITE_ENABLE_SPECULATION=true` / `VITE_ENABLE_SPOT_TRADE=true` وب، first-paint برابر **۱۷۰۹٫۵۵ / ۱۷۵۰ KB** بود. باندل واقعی Vite شامل `Perp-CaDZquNy.js → FuturesHistory-B0Rb_B-5.js` بود؛ چانک مقصد `fhist-title` و ستون PnL «—» را دارد. تست Vite جداگانه نیز `FUTURES_HISTORY_ENABLED === true` را از همان build-time flag اثبات کرد. `DYDX_TPSL_ENABLED` false ماند.

`npm run build:full` عمداً اجرا نشد: اسکریپت علاوه بر build vendor و سایت، SEO strict، IndexNow submit و API verification را هم اجرا می‌کند. مسیر build وب با همان فایل rollout و همان فرمان Vite واقعی build شد؛ این محدودیت شفاف است و جای CI/deploy نهایی را نمی‌گیرد.
