# FBT CENTRAL INTELLIGENCE OS

## مغز مرکزی FBT — معماری، پیاده‌سازی و قوانین

> نسخه: `fbt.central-intelligence-os.v1.0`
> وضعیت: پیاده‌سازی شده در `server/central/` + درگاه‌های `/api/*` + تب «مغز مرکزی» در صفحهٔ Intent OS

---

## ۱) اصل بنیادی

این سیستم یک Chatbot نیست. **یک مغز مرکزی** است که همهٔ ماژول‌های FBT
(Wallet، Swap، Bridge، Lending، Futures، dYdX، Portfolio، Goals، News،
Signals و…) را به‌صورت **اندام‌های یک سیستم واحد** به هم متصل می‌کند:

```
Single Brain / Multiple Modules / Shared State / Unified Actions / Verified Execution
```

قانون نهایی: **LLM هرگز Source of Truth نیست.** Source of Truth سرویس‌های
واقعی‌اند (کیف پول کاربر، بازار، بلاکچین، پروتکل‌های Lending و…). مغز فقط:
فهمیدن، استدلال، برنامه‌ریزی، انتخاب ابزار، هماهنگی و توضیح را انجام می‌دهد.

## ۳) درگاه یکپارچه (Central API — §36)

```
POST /api/intent                 نیت جدید کاربر
GET  /api/intent/:id             رکورد کامل نیت (برنامه، نتایج ابزار، ردپا)
POST /api/intent/:id/confirm     تأیید صریح (قفل اجرای §33)
POST /api/intent/:id/cancel      لغو نیت در انتظار

GET  /api/system/state           State یکپارچهٔ سیستم (§4)
GET  /api/system/health          سلامت + پوشش ماژول‌ها + آمار رویدادها
GET  /api/system/capabilities    نقشهٔ قابلیت‌ها (§8)
GET  /api/system/events          جریان رویدادها (§15)
GET  /api/system/modules         فهرست ماژول‌ها + ممیزی §40
GET  /api/system/memory          حافظهٔ گفتگوی جلسه

POST /api/tools/read | quote | prepare | simulate | execute | verify
                                 دسترسی مستقیم به مسیریاب ابزار (§9)

GET  /api/transactions/:id       تراکنش/اکشن + تأیید
```

**قانون §37:** فرانت‌اند فقط همین درگاه را صدا می‌زند. کلاینت مرورگر در
`src/lib/centralClient.js` پیاده شده است.

## ۵) ماشین وضعیت نیت (§32)

```
RECEIVED → UNDERSTANDING → CONTEXT_RESOLUTION → STATE_INSPECTION →
PLANNING → POLICY_CHECK → QUOTE → SIMULATION → CONFIRMATION →
EXECUTION → VERIFICATION → STATE_UPDATE → COMPLETED
```

مسیر خطا: `خطا ← طبقه‌بندی ← بازیابی ← تلاش مجدد ← مسیر جایگزین ← تأیید`
یا برای خطای امنیتی: `خطا ← توقف امنیتی` (هرگز دور زده نمی‌شود).

### مدل دسترسی (§33)

- **READ** — تحلیل/بازار/اخبار/سیگنال: بدون تأیید.
- **PREPARE** — نقل‌قول/شبیه‌سازی/آماده‌سازی: هرگز اجرا نمی‌شود.
- **EXECUTE** — سواپ/بریج/وام/فیوچرز/ریبالانس: **همیشه** تأیید صریح لازم است.
  سرور هرگز امضا نمی‌کند؛ تراکنشِ امضانشده به کیف پول کاربر تحویل می‌شود.

### ضدتکرار (§34)

`requestId | intentId | executionId` کلید یکتا می‌سازند؛ درخواست تکراری همان
اکشن قبلی را برمی‌گرداند. کلیک مضاعف هرگز معاملهٔ دوم نمی‌سازد.

## ۶) هوش بین‌ماژولی و سناریوها (§42)

همهٔ سناریوهای §42 در `test/central-os-probe.mjs` قفل شده‌اند (۶۰ ادعا):

- **A** بررسی پرتفوی → اعداد واقعی + ریسک تمرکز
- **B** «BTC زیاد دارم؟» → محاسبهٔ تمرکز (نه حدس)
- **C** «بفروشم؟» → حل دارایی از حافظهٔ گفتگو، بدون پرسش مجدد
- **D** سواپ → نقل‌قول ← قفل تأیید؛ قبل از تأیید هیچ‌چیز اجرا نمی‌شود
- **E** «بعدش به Arbitrum ببر» → برنامهٔ ترکیبی سواپ + بریج
- **F** «وامم چقدر امنه؟» → Health Factor از فرمول واقعی
- **G** «اگر BTC ۳۰٪ بریزد» → سناریوی دقیق روی پرتفوی واقعی
- **I** خرابی فراهم‌کننده → تشخیص ← تلاش مجدد ← مسیر جایگزین ← ادامه
- **J** ناهنجاری امنیتی → توقف فوری؛ سیاست امنیتی هرگز دور زده نمی‌شود

اجرا: `npm run test:central-os`

## ۷) صداقت (Honesty)

- دادهٔ در دسترس نبود → `dataStatus: 'unavailable'`؛ **هرگز حدس نمی‌زند**.
- جملات ممنوع §20 («متوجه شدم»، «چطور می‌توانم کمکتان کنم»، …) اگر داده هست
  هرگز ارسال نمی‌شوند؛ پروب روی همهٔ پاسخ‌ها این را بررسی می‌کند.
- رویدادها و لاگ‌ها هرگز کلید خصوصی/سید ذخیره نمی‌کنند (§35).
- قابلیتِ موجود ادعا نمی‌شود و قابلیتِ موجود انکار نمی‌شود (§8).

## ۸) قانون نهایی توسعه‌دهندگان (§40/§45)

هر Feature جدید **باید** خودش را به مغز مرکزی معرفی کند و این موارد را ثبت کند:

```
Capability · Tool · State · Health · Read · Quote · Prepare · Simulate ·
Execute · Verify · Error · Recovery · Fallback · Events · Permissions
```

اگر یکی کم باشد: **Feature = INCOMPLETE** (در `/api/system/modules` قابل مشاهده است).

> **Prompt فقط رفتار AI را تعریف می‌کند؛ معماریِ مرکزی ابزار، State، Context
> و اجرای واقعی را فراهم می‌آورد.** برای هر مشکل جدید، دیگر Prompt اضافه
> نمی‌کنیم — ماژول را به مغز وصل می‌کنیم.
