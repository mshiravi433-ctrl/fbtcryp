# ارتقای سئو، صفحات لندینگ و معرفی اف بی تی — ۲۰۲۶-۱۰-۱۳

## اصلاح جای متن‌ها و لینک‌های موضوعی

- در قالب مشترک لندینگ‌ها، لوگو اولین بخش قابل‌مشاهدهٔ هدر است. بردکرامب بعد از لوگو می‌آید؛ ردیف موضوع‌ها به پایین محتوای صفحه و پس از هشدار ریسک منتقل شده است.
- محتوای مرجع صفحهٔ اصلی در **ترتیب واقعی HTML** بعد از `#root` قرار دارد، نه با جابه‌جایی ظاهری CSS. پس از راه‌اندازی اپ هم حذف نمی‌شود و بازدیدکنندهٔ صفحهٔ اصلی وب می‌تواند آن را بخواند.
- در مسیرهای عملیاتی مانند `#/swap`، `#/wallet` و `#/intent` و در اپ بومی، این فوتر نمایش داده نمی‌شود؛ برگشت به صفحهٔ اصلی همان محتوا را بدون حذف و بازسازی برمی‌گرداند. این تصمیم بر اساس مسیر و پلتفرم است، نه تشخیص خزنده.
- بدون JavaScript، ریشهٔ خالی اپ و لایهٔ بوت پنهان می‌شوند تا یک صفحهٔ خالی بالای راهنماها باقی نماند.
- برای جلوگیری از بازگشت مشکل، ژنراتور اگر جای بلوک مرجع قبل از ریشهٔ اپ باشد، ساخت را رد می‌کند. کنترل زبان در هدر موبایل هم داخل محدودهٔ کارت می‌ماند.

## شش صفحهٔ تازه برای سه نیاز جست‌وجو

| موضوع | فارسی | انگلیسی |
|---|---|---|
| معرفی FBT / FBTSwap / اف بی تی و تشخیص دامنهٔ رسمی | `/fa/fbt-swap` | `/fbt-swap` |
| سود با کریپتو، محاسبهٔ نتیجهٔ خالص و ریسک | `/fa/crypto-profit-and-risk` | `/crypto-profit-and-risk` |
| «صرافی بدون تحریم؟» و تفاوت نبود KYC با نبود محدودیت | `/fa/crypto-access-and-restrictions` | `/crypto-access-and-restrictions` |

این‌ها صفحه‌های واقعی و مستقل با متن آموزشی، جدول واقعیت‌ها، پرسش و پاسخ، هشدار ریسک، نویسندهٔ سازمانی و تاریخ انتشار هستند؛ نه صفحه‌های تکراری برای شکل‌های مختلف یک کلمه.

- صفحهٔ برند معنی FBT Swap، FBTSwap، Swap و Crypto را تفکیک می‌کند. نماد یک توکن با نام FBT به‌تنهایی تأیید یا وابستگی به محصول را ثابت نمی‌کند.
- صفحهٔ سود، هزینهٔ واقعی و تفاوت APY با درآمد ثابت را توضیح می‌دهد. مثال عددی به‌صراحت فرضی است: رشد ناخالص ۱۰ دلاری با فرض‌های بیان‌شده به زیان خالص ۱۶٫۰۷ دلار می‌رسد. هیچ وعدهٔ بازده وجود ندارد.
- صفحهٔ محدودیت‌ها ادعای «بدون تحریم» نمی‌کند: نبود احراز هویت اف بی تی، قانون، شرط ارائه‌دهنده یا کنترل صادرکنندهٔ توکن را حذف نمی‌کند. متن نظر حقوقی یا دستور دور زدن محدودیت نیست.

## ارتقای فنی و اطلاعات قابل استناد

- نام‌های واقعی برند در `Organization` و `WebSite` صفحهٔ اصلی و تمام لندینگ‌ها یکسان شده‌اند؛ واژه‌های عمومی Swap و Crypto به‌عنوان نام شرکت جا زده نشده‌اند.
- عنوان، توضیح، Open Graph، کارت اشتراک‌گذاری و اطلاعات ساختاریافتهٔ صفحهٔ اصلی هماهنگ‌اند.
- هر سه جفت صفحه در هاب موضوعی، کتابخانه، لینک‌های پایین صفحات و محتوای مرجع صفحهٔ اصلی قابل کشف هستند؛ لینک مرتبطِ انتخاب‌شده پیش از لینک‌های عمومی هم‌موضوع نمایش داده می‌شود.
- بردکرامب قابل‌مشاهدهٔ مقاله‌ها با سلسله‌مراتب دادهٔ ساختاریافته مطابقت دارد. صفحهٔ نویسنده و سیاست محتوا از کنار تاریخ در دسترس‌اند؛ تاریخ ویرایش فقط وقتی با تاریخ انتشار فرق دارد جدا نشان داده می‌شود.
- نقشه‌های سایت زبان‌محور، `xhtml:link` برای hreflang خودارجاع و دوطرفه دارند و از همان جفت‌های ترجمهٔ HTML ساخته می‌شوند. تاریخ واقعی تغییر صفحهٔ اصلی و لندینگ اصلی نیز در نقشهٔ سایت آمده است؛ تاریخ مقاله‌های قدیمی صرفاً به‌خاطر ساخت دوباره عوض نشده است.
- صفحات عمومی اجازهٔ خلاصهٔ جست‌وجو و پیش‌نمایش مناسب می‌دهند. فایل‌های XML و TXT با UTF-8 و کش کوتاه سرو می‌شوند؛ پاسخ‌های API دستور `noindex` دارند.
- `/index.html` و درخواست‌های میزبان `www.fbtswap.ir` به نشانی اصلی ریدایرکت دائمی دارند؛ ریدایرکت‌های قدیمی صفحات فارسی حفظ شده‌اند. قانون میزبان www فقط در صورت رسیدن درخواست آن میزبان به همین پروژه اعمال می‌شود و DNS را ایجاد نمی‌کند.
- `llms.txt` و `llms-full.txt` معرفی برند و مرز ادعاهای سود و دسترسی را روشن می‌کنند و به مقالهٔ مربوط پیوند می‌دهند. مجاز بودن خزنده‌های جست‌وجو با استفادهٔ آموزشی مدل‌ها یک چیز نیست؛ این فایل‌ها تضمین استناد در پاسخ هوش مصنوعی نیستند.

## آزمون‌ها و جلوگیری از بازگشت خطا

| بررسی | نتیجهٔ محلی |
|---|---|
| `npm run build:full`، شامل ساخت Vite و بارگذاری ورودی API | موفق |
| `npm run seo:audit:strict` | ۲۵۹ URL قابل ایندکس در خروجی، صفر خطا، صفر هشدار |
| `npm run test:seo` | ۲۴ تست موفق |
| `npm run test:landing` | ۱۲۷ بررسی موفق |
| `npx vitest run test/web-entry.test.js` | ۱۲ تست موفق؛ رفتار ورود اپ تغییر نکرده است |

خروجی شامل ۲۵۸ لندینگ و راهنما به‌اضافهٔ صفحهٔ اصلی است. با احتساب ۱۵ استاب ریدایرکت `noindex`، ۲۷۴ سند HTML وجود دارد. نقشهٔ سایت ۱۵۵ URL در فایل انگلیسی و ۱۰۴ URL در فایل فارسی دارد؛ ۲۳۷ URL تاریخ ویرایش محتوایی دارند.

شش سناریوی مرورگر Chromium نیز بررسی شده‌اند: صفحهٔ اصلی بدون JavaScript روی موبایل، دو راهنمای فارسی روی موبایل، راهنمای انگلیسی روی دسکتاپ، تغییر زبان لندینگ اصلی و باقی‌ماندن فوتر پایین اپ پس از mount و رفت‌وبرگشت مسیر. منابع بیرونی در این آزمون عمداً قطع بودند؛ دادهٔ بازار واقعی یا کیفیت اتصال تولید با آن تأیید نشده است.

بررسی سخت‌گیرانه اکنون جزو `build:full` است و روی هر ساخت تولید اجرا می‌شود. قالب اختیاری workflow آزمون‌های PR و `main` در `ci/seo.yml` آماده است، اما فعال نیست: مجوز اتصال فعلی GitHub اجازهٔ ایجاد فایل جدید در `.github/workflows/` را نمی‌دهد. نصب آن در مسیر workflow نیازمند مجوز مربوط است؛ انتشار کد سایت به آن وابسته نیست. فقدان متن مرجع، برگشت ردیف موضوع‌ها به هدر، ناسازگاری hreflang، تاریخ نادرست و ناسازگاری نام برند ساخت را متوقف می‌کنند. اشکال موجود lockfile لینوکس نیز با همان ابزار موجود مخزن و تنها افزودن `optional: true` برای fsevents مخصوص macOS رفع شده است؛ نسخهٔ وابستگی‌ها تغییر نکرده است.

## IndexNow و گوگل: مرز نتیجهٔ قابل اثبات

IndexNow به‌صورت پیش‌فرض فقط در ساخت Production اجرا می‌شود؛ PR، پیش‌نمایش و ساخت محلی نباید برای صفحهٔ منتشرنشده اعلان بفرستند. اجرای دستی صریح با `--submit` و بررسی بدون شبکه با `--dry-run` ممکن است. درخواست واقعی مهلت ۱۰ ثانیه دارد و شکست اعلان مانع انتشار نیست. فقط URLهای واقعیِ نقشهٔ سایت با تاریخ معتبرِ اخیر انتخاب می‌شوند؛ مسیرهای هش‌دار ارسال نمی‌شوند.

**IndexNow برای گوگل نیست.** پذیرش اعلان، آماده بودن HTML یا موفقیت استقرار هیچ‌کدام به معنی ایندکس یا رتبهٔ قطعی نیست. متای تأیید مالکیت موجود حفظ شده است، اما وجود آن وضعیت فعلی حساب Search Console را اثبات نمی‌کند.

پس از استقرار تولید، مالک سایت باید در Search Console:

1. `https://fbtswap.ir/sitemap.xml` را ثبت یا وضعیت نقشهٔ ثبت‌شده را بررسی کند.
2. صفحهٔ اصلی، لندینگ اصلی و سه صفحهٔ فارسی جدید را با URL Inspection بررسی و در صورت لزوم Request indexing کند.
3. گزارش Performance را برای FBT، FBTSwap، اف بی تی، سواپ، سود با کریپتو و عبارت‌های دقیق‌تر پیگیری کند.
4. پوشش صفحات فارسی و انگلیسی، canonical انتخاب‌شدهٔ گوگل و Core Web Vitals را پس از جمع شدن دادهٔ واقعی پایش کند.

زمان خزش، انتخاب نتیجه، رتبه و استناد در جست‌وجوی هوش مصنوعی در اختیار موتور جست‌وجو است. این ارتقا کیفیت محتوا و آمادگی فنی را بهتر می‌کند؛ هیچ رتبهٔ اول، زمان نمایش فوری یا نتیجهٔ سرمایه‌گذاری وعده داده نشده است.
