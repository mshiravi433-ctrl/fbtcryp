## بخش صفر: چیزهایی که من نمی‌توانم برایت انجام دهم

صادق باشم درباره مرزها، چون وقتت را تلف نکنم:

| کار | چه کسی | چرا |
|---|---|---|
| ساخت فایل `.aab` | GitHub Actions | این سندباکس نه JDK دارد نه Android SDK — نمی‌تواند APK بسازد |
| ساخت کلید امضا | **فقط تو** | اگر من بسازمش، من کلید اپ تو را دارم. این کلید مثل عبارت بازیابی کیف پول است |
| ثبت‌نام Play Console | تو | ۲۵ دلار یک‌بار، نیاز به کارت و احراز هویت |

من کد را آماده کرده‌ام، مشکلات انتشار را رفع کرده‌ام، و workflow را نوشته‌ام.

## ۲. ساخت کلید امضا (روی گوشی، با Termux)

**این مهم‌ترین فایل کل پروژه است.** گوگل لیست اپ تو را برای همیشه به این کلید
گره می‌زند. اگر گمش کنی نمی‌توانی اپ خودت را آپدیت کنی — باید لیست جدید با نام
پکیج جدید بسازی و همه نصب‌های قبلی یتیم می‌شوند.

```bash
pkg install openjdk-17 -y
cd ~ && curl -O https://raw.githubusercontent.com/mshiravi433-ctrl/fbtcryp/arena/019fa8cd-fbtcryp/ci/make-keystore.sh
bash make-keystore.sh
```

اسکریپت چهار مقدار چاپ می‌کند. **همه را جای امنی ذخیره کن** (کاغذ + یک نسخه
رمزگذاری‌شده در جای دیگر — نه فقط روی همان گوشی).

## ۳. تنظیم GitHub

### Secrets
`Settings → Secrets and variables → Actions → New repository secret`

| نام | مقدار |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | خروجی base64 اسکریپت |
| `ANDROID_KEYSTORE_PASSWORD` | رمزی که انتخاب کردی |
| `ANDROID_KEY_ALIAS` | `fbt` |
| `ANDROID_KEY_PASSWORD` | رمز کلید |

### Variables (اینها عمومی‌اند، secret نیستند)
`همان صفحه → Variables → New repository variable`

| نام | مقدار |
|---|---|
| `VITE_API_BASE` | `https://<اپ-ورسل-تو>.vercel.app/api` |
| `VITE_WALLETCONNECT_PROJECT_ID` | از cloud.reown.com |
| `VITE_VAPID_PUBLIC_KEY` | کلید عمومی VAPID (بخش ۵) |

**`VITE_API_BASE` را جدی بگیر.** اپ اندروید صفحاتش را از `https://localhost`
سرو می‌کند، پس مسیر نسبی `/api` به هیچ‌جا نمی‌رسد. بدون آن، اخبار و رتبه‌بندی و
هوش مصنوعی سمت سرور کار نمی‌کنند.

### Workflow
محتوای `ci/build-release.yml` را در ویرایشگر وب گیت‌هاب داخل فایل
`.github/workflows/build-release.yml` بگذار. (توکن من اجازه نوشتن در آن مسیر
را ندارد — محدودیت گیت‌هاب است، نه انتخاب من.)

بعد: `Actions → Build signed release → Run workflow`، شماره نسخه را بده.

خروجی: `play-release-bundle` شامل `app-release.aab`.

## ۴. Play Console

۱. ثبت‌نام: <https://play.google.com/console> (۲۵ دلار، یک‌بار)
۲. Create app → نام، زبان پیش‌فرض، Free
۳. **App content** — این بخش را کامل پر کن وگرنه انتشار بلاک می‌شود:

| سوال | پاسخ برای این اپ |
|---|---|
| Privacy policy | لینک صفحه `#/legal/privacy` |
| Ads | بله (بنر داخلی دارد) |
| App access | همه بخش‌ها بدون لاگین در دسترس است |
| Content rating | پرسشنامه را پر کن — **صادقانه** |
| Target audience | ۱۸+ |
| Data safety | پایین را ببین |
| Financial features | **بله** — این را حتماً درست پر کن |

### Data safety — چه چیزی جمع می‌شود

اپ تو واقعاً کم جمع می‌کند و همین را بگو:

- **جمع نمی‌شود:** نام، ایمیل، شماره تلفن، مکان، مخاطبین
- **جمع می‌شود:** آدرس کیف پول (اختیاری، وقتی وصل کند)، نام نمایشی (اختیاری)
- **رمزگذاری در انتقال:** بله
- **قابل حذف:** بله — «ری‌ست حساب» در تنظیمات

عبارت بازیابی هرگز از دستگاه خارج نمی‌شود؛ در Data safety اعلامش نکن چون
جمع‌آوری نمی‌شود.

### بخش مالی — جایی که بیشتر اپ‌های کریپتو رد می‌شوند

گوگل برای اپ‌های کریپتو سخت‌گیر است. سه نکته که به نفع توست:

۱. **غیرحضانتی است.** تو دارایی کاربر را نگه نمی‌داری. این را صریح بنویس.
۲. **صرافی نیستی.** یک رابط برای صرافی‌های غیرمتمرکز هستی.
۳. **بخش‌های مجازی را جدا اعلام کن.** پیش‌بینی و سرمایه‌گذاری با اعتبار مجازی
   کار می‌کنند و در خود اپ هم همین نوشته شده.

⚠️ **هشدار جدی درباره بخش بازی‌ها:** گوگل محتوای شبیه‌قمار را سخت محدود می‌کند.
حتی با امتیاز بی‌ارزش، Crash و Dice و Mines برای بازبین گوگل قمار به نظر
می‌رسند. **قویاً توصیه می‌کنم برای بیلد Play این را بگذاری:**

```
VITE_DISABLE_GAMES=true
```

این کار مسیرها را کاملاً حذف می‌کند، نه فقط مخفی — کد داخل APK هم نمی‌رود.
احتمال رد شدن را به‌شدت کم می‌کند.

## ۵. پوش نوتیفیکیشن

### درباره SignalWire — یک تصحیح لازم

مقادیری که فرستادی (Project ID، Space URL، Signing key) برای **SignalWire**
هستند. SignalWire یک پلتفرم **SMS، تماس صوتی و ویدیو** است — سرویس Web Push
مرورگری ارائه نمی‌دهد.

پس آنها را در کد نگذاشتم. اگر می‌گذاشتم، یک اتصال بی‌کار می‌ساختم که شبیه
قابلیت به نظر می‌رسد و هیچ نوتیفیکیشنی نمی‌فرستد.

**آن Signing key را باطل کن.** در چت فرستادی‌اش، پس دیگر محرمانه نیست.

اگر بعداً SMS خواستی (مثلاً کد تایید)، SignalWire گزینه خوبی است و آن موقع
وصلش می‌کنم.

### چیزی که واقعاً کار می‌کند: Web Push با VAPID

کلیدها را برایت ساختم:

```

VAPID_PRIVATE_KEY=aA6pkHP54EwvnmYcRMbOINUvOVxX04tc9wgRjw2g460
CRON_SECRET=c8Rq2oKmCg3N3OZBYZ0RAPUEx8tAImsM
```

⚠️ چون اینها را در چت می‌بینی، **محرمانه نیستند**. برای تولید واقعی خودت

| `VAPID_PRIVATE_KEY` | **فقط سرور** |
| `CRON_SECRET` | **فقط سرور** |

## ۶. Vercel Blob — تنظیمش کردی، حالا وصلش کن

Storage را باز کرده‌ای. حالا فقط این را در Environment Variables بگذار:

```
BLOB_READ_WRITE_TOKEN=<توکنی که در داشبورد Vercel می‌بینی>
```

⚠️ توکنی که در چت فرستادی هم دیگر محرمانه نیست. در داشبورد Vercel یک
توکن جدید بساز و قبلی را باطل کن.

بدون این، جدول رتبه‌بندی و اشتراک‌های پوش با هر کولد استارت پاک می‌شوند —
اپ خودش تشخیص می‌دهد و صادقانه «فقط روی دستگاه» می‌نویسد.

## ۷. Cron — تست شد و کار می‌کند

`vercel.json` تنظیم شده:

```json
"crons": [{ "path": "/api/cron/daily", "schedule": "0 9 * * *" }]
```

**درباره کدی که فرستادی:** آن snippet برای Next.js بود (`next/server` و
`NextResponse`). این پروژه **Vite + Express** است، پس آن import ها وجود ندارند
و بیلد را می‌شکستند. معادلش را با Express نوشتم.

سه اندپوینت داری:

| مسیر | کار |
|---|---|
| `GET /api/cron/status` | بدون فرستادن چیزی می‌گوید چه چیزی جلوی ارسال را گرفته |
| `GET /api/cron/daily` | همان که Vercel Cron صدا می‌زند |
| `POST /api/push/daily` | برای زمان‌بندهای دیگر |

بعد از دیپلوی، این را در مرورگر باز کن:

```
https://<اپ-تو>.vercel.app/api/cron/status
```

جواب دقیقاً می‌گوید چه چیزی کم است:

```json
{ "cronSecretSet": true, "pushConfigured": true, "wouldSend": true, "blockedBy": null }
```

تست کردم: بدون توکن ۴۰۱ می‌دهد، با توکن درست اجرا می‌شود، و مقایسه رمز
timing-safe است.

## ۸. کارمزد — تایید شد که به حساب تو می‌رود

این را جدی گرفتم چون پول توست.

**چطور کار می‌کند:** ما کارمزد را با پارامتر درخواست می‌کنیم، ولی چیزی که
واقعاً روی زنجیره اجرا می‌شود `routeSummary.extraFee` است — همان که داخل
calldata امضا می‌شود.

**خطری که پیدا کردم:** اگر aggregator پارامترهای ما را نادیده می‌گرفت (آدرس
اشتباه، تغییر API، کارمزد بزرگ‌تر از مبلغ)، سواپ **موفق** می‌شد، کاربر گس
می‌داد، و تو **هیچ** نمی‌گرفتی — بی‌سروصدا، شاید هفته‌ها.

**رفع:** حالا در دو نقطه چک می‌شود:
- موقع قیمت‌گیری
- **دقیقاً قبل از امضا** (چون ممکن است قیمت مدتی روی صفحه مانده باشد)

اگر `extraFee` نباشد یا آدرسش با آدرس تو یکی نباشد، تراکنش با
`FEE_NOT_APPLIED` یا `FEE_RECIPIENT_MISMATCH` متوقف می‌شود. آدرس نادرست بدتر
از کارمزد صفر است — یعنی پول به جیب کس دیگری می‌رود.

**خودت تست کن:**

```bash
node scripts/verify-fees.mjs
```

هر ۹ شبکه را زنده چک می‌کند و اگر جایی خراب باشد با کد خطا خارج می‌شود.
(در سندباکس من اینترنت خروجی نیست، پس آنجا اجرا نشد — روی سیستم خودت بزن.)

**تایید نهایی روی زنجیره:** بعد از اولین سواپ واقعی، آدرست را در BscScan باز
کن و در تب Internal Txns دنبال ورودی از روتر KyberSwap بگرد. آنجا حقیقت است،
نه کد من.

## ۹. ترجمه‌ها — وضعیت واقعی

اینجا باید صریح باشم چون خواستی «کامل و بدون نقص» باشد.

| زبان | پوشش |
|---|---|
| انگلیسی | ۱۰۰٪ (زبان مبدأ) |
| فارسی | ۹۷٪ |
| عربی | ۳۸٪ |
| ۹ زبان دیگر | ۳۳٪ هر کدام |

**چرا ۱۰۰٪ نیست:** اپ ۱۰۹۹ رشته دارد. ۹ زبان × ۱۰۹۹ = حدود ۱۰٬۰۰۰ ترجمه.
آنچه تحویل داده‌ام ۳۶۶ کلید در هر زبان است که **همه سطوحی که کاربر واقعاً
لمس می‌کند** را پوشش می‌دهد: ناوبری، سواپ، کیف پول، بازار، تنظیمات، اخبار،
سیگنال‌ها، آموزش اولیه، و **تمام هشدارهای ایمنی و قانونی**.

آنچه نیست: متن‌های حقوقی طولانی، راهنمای مفصل، توضیحات بخش بازی‌ها و
اکوسیستم. اینها به انگلیسی fallback می‌شوند، **نه به کلید خام**.

**یک چیز را عمداً انجام ندادم:** ترجمه ماشینی انبوه. اگر ۱۰٬۰۰۰ رشته را از
ماشین رد می‌کردم عدد ۱۰۰٪ می‌شد، ولی هشدارهایی مثل «عبارت بازیابی را گم کنی
دارایی برای همیشه رفته» ممکن بود غلط ترجمه شوند و کاربر با اعتماد به آن ضرر
کند. عدد قشنگ‌تر می‌شد، اپ خطرناک‌تر.

**درباره ادعای قبلی:** فلگ دستی می‌گفت عربی «کامل» است. شمردم: ۶۸۶ رشته هنوز
عیناً انگلیسی بودند. حالا پوشش **محاسبه** می‌شود نه اعلام، و پیکر زبان همان
درصد واقعی را نشان می‌دهد.

اگر کامل شدن هر ۱۰ زبان اولویت است، بگو تا در نوبت بعد ادامه بدهم — هر بخش
حدود ۳۰۰ رشته است.
